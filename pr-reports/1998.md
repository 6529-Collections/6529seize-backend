## Summary

Help6529 can answer Desktop onboarding and local-node recovery questions with complete procedures. Desktop questions and contextual follow-ups retrieve scoped Core knowledge before public-data planning; ordinary website/mobile questions exclude Core procedures.

## What Changed

- Preserve the complete primary procedure and its warnings, with bounded 1600-token/6000-character Desktop replies. Truncated or failed generation falls back to complete numbered facts.
- Require substantive topic relevance so targeted TDH, transaction, NFT, wallet, and IPFS questions retrieve the intended procedure.
- Cold corpus-load failures use the processor technical-failure/refund path; only a loaded corpus without matching knowledge produces a no-source escalation.
- Explicit mobile/browser targets stay outside Core even when the question mentions Core. Desktop-versus-website TDH comparisons and contextual follow-ups retain their validated scope.
- Fail closed when Desktop knowledge is unavailable. Existing app-download and device-connection records remain usable.
- Keep the production corpus frontend-owned; the backend snapshot is exclusively a regression fixture.

## Release Notes

Desktop support includes onboarding and recovery guidance without remote device inspection or control. Deploy this runtime first: it safely declines unsupported procedures until the new corpus arrives. Publishing the new corpus before upgrading the runtime can misroute generic wallet questions or truncate the new procedures. No Core release is required.

## Risks / Follow-Ups

Longer answers still share the existing model timeout; timeout fallback preserves the procedure. Coordinate a rollback of the new corpus before reverting the runtime policy. Knowledge describes pinned Core behavior and must be reviewed when native controls change.

Full local TypeScript compilation is limited by missing API-only dependency declarations/modules in the available dependency tree (`js-yaml`, `@serverless/typescript`, `aws-serverless-express`, `swagger-ui-express`, and `@aws-sdk/client-managedblockchain`). The affected API files and manifests are unchanged from the PR base; no unrelated dependency fix is included.
