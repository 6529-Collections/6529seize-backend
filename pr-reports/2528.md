# PR Report: Rebuild the Ethereum indexes from empty; artists and Meme Lab royalties tables

PR: [PR #2528](https://github.com/6529-Collections/6529seize-backend/pull/2528)
Base: #2527, which stacks on #2522

## Summary

6529.io's MySQL should hold only an index that can be dropped and rebuilt from Ethereum, content-addressed files and this repository. This PR adds the steps that rebuild the transactions, the NFT catalogue, NFT history and the holdings tables from empty with the live loops' own code. It records the Memes edition-size floors in a reviewed file behind a flag. It also creates the `artists` and `meme_lab_royalties` tables, which no entity or migration made, so a fresh database answered 500 on `/api/memes/artists_names` and `/api/memes-mint-stats/total`. A test runs the steps against a small local Ethereum and checks they write what the live loops write.

## What Changed

- **Rebuild steps** (`src/holdings/ethereum-index-rebuild.ts`), in order: transactions (Memes, Gradients, Meme Lab) to the run's Ethereum mark; NFT owners; the NFT catalogue with its artists, extended data and seasons; NFT history; activity and balances.
- **Rebuild mode** (`src/holdings/rebuild-mode.ts`, an `AsyncLocalStorage`): inside a step, no "is Live!" announcement, no media upload job, no ENS lookup, and no mint stats or subscription writes. A live loop in the same process stays outside it.
- **NFT history rebuild** (`src/nft-history/history-rebuild.ts`): finds the blocks that hold history sources in wide ranges, runs the loop's own ingestion on each, and resumes after the stored checkpoint.
- **Edition-size floors** (`src/nftsLoop/memes-edition-size-floors.json`), behind `FEATURE_ETH_INDEX_REBUILD_FIXES`: a recorded floor replaces a rebuilt row's; a floor read from the chain in the same run still wins. The file is empty until the team's export.
- **Two tables** (`ArtistEntity`, `MemeLabRoyaltyEntity`, `synchronize: false`): `dbMigrationsLoop`'s full scope creates each when it is missing and changes none that exist.
  - `artists` rebuilds from the cards' metadata; the hand-typed bio, picture, works and links are not rebuilt, and no route serves them.
  - `meme_lab_royalties` rebuilds from `src/holdings/meme-lab-royalties.json` (`rebuildMemeLabRoyalties`). It refuses while the file has no splits, and leaves the table as it is.

## Backend Impact

**Deploy, flag off, any order:** `dbMigrationsLoop` (full scope), `nftsLoop`, `nftHistoryLoop`, `transactionsLoop`, `ownersBalancesLoop`.

**Schema.** `CREATE TABLE IF NOT EXISTS artists` and `meme_lab_royalties`, which do nothing where the tables exist. No other change.

**Live behaviour.** Unchanged outside rebuild mode, which no Lambda enters. The NFT loop's refresh reconciles artists as before.

**Other services.** No API, frontend, schedule, queue or alarm change.

## Config / Env

| Flag | Lambdas | When it goes on |
| --- | --- | --- |
| `FEATURE_ETH_INDEX_REBUILD_FIXES` | `nftsLoop` (and `marketStatsLoop`, from the base PR) | once the floors file holds the team's export |

**Team asks** (read-only, on the primary, in the application schema):
1. `SHOW CREATE TABLE artists; SHOW CREATE TABLE meme_lab_royalties;`: if a type differs from the entities, we match them.
2. Export `SELECT token_id, primary_royalty_split, secondary_royalty_split FROM meme_lab_royalties ORDER BY token_id;` into `src/holdings/meme-lab-royalties.json`.
3. Export the Memes floors with the query in the PR text into `src/nftsLoop/memes-edition-size-floors.json`.
4. If the artists' hand-typed fields should survive a rebuild, keep a private export of them.

## Rollback

- **Floors:** set `FEATURE_ETH_INDEX_REBUILD_FIXES` to `false`; the file is then ignored.
- **Tables:** nothing to roll back; a redeploy from an earlier ref leaves them in place.

## Risks / Follow-Ups

- **NextGen** has no rebuild step yet.
- **Identical NFT history** needs the provider's logs and archive state, and every metadata file still served.
- **Production's column types** for the two tables are unconfirmed until ask 1; the entities can't alter them either way.
- **Tests.** The MySQL tests, including the from-empty test against the live loops, ran on a development server; CI runs them on its own MySQL.
