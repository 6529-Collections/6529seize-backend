# PR Report: Drop Forge Creator Admin Authorization

PR: [Backend #2134](https://github.com/6529-Collections/6529seize-backend/pull/2134)
Branch: `agent-prxt/drop-forge-onchain-admins` -> `main`
Related PRs: [Frontend #4160](https://github.com/6529-Collections/6529seize-frontend/pull/4160)

## Summary

Configured claims admins, the mainnet Memes creator owner, and approved
on-chain admins can read and update Drop Forge claim-action tracking.

## What Changed

- All three tracking routes use the authenticated wallet and the same
  authorization boundary before reading or changing claim state.
- On-chain-only callers require a fresh `isAdmin(wallet)` result from the fixed
  mainnet Memes creator. False results deny access; failed/malformed/timed-out
  verification returns 503. Approval results are not cached across requests.
- Configured claims admins retain access without RPC verification. Actor
  attribution, stored action shapes, and craft permissions are unchanged.
- OpenAPI and architecture documentation reflect the new authorization. API
  artifacts were regenerated and the frontend spec synchronized; model shapes
  are unchanged.

## Backend Impact

- Changed service: `api` only. No new services, queues, entities, or migrations.
- The existing mainnet RPC provider now participates in tracking authorization.
- These endpoints cannot approve/revoke admins or transfer contract ownership.

## Config / Env

No new variables. `CLAIMS_ADMIN_WALLETS` remains an independent access grant;
the existing mainnet RPC configuration is required for on-chain-only callers.

## Backend Deployment

Deploy `api` before the companion frontend. Not deployed by request; no other
Lambda or migration is required.

## Risks / Follow-Ups

- RPC unavailability denies on-chain-only tracking access, rather than keeping
  stale grants. Configured claims admins remain unaffected.
- Revoking an on-chain grant does not remove independently configured
  `CLAIMS_ADMIN_WALLETS` access.
- Unsupported contracts, including Sepolia tracking, remain unsupported.

## Release Notes

Approved creator admins can complete the Launch tracking workflow without
being added to an environment admin list. No mint revenue routing changes.
