# PR Report: Parallel backend PR tests

PR: https://github.com/6529-Collections/6529seize-backend/pull/2124
Branch: `agent-prxt/parallel-backend-pr-ci` -> `main`

## Summary

Run the four existing Jest shards on separate GitHub Actions runners alongside
lint, formatting, generated-file verification, and backend/API builds. This
reduces the sequential test wait while retaining the full test suite.

## What Changed

- Each shard keeps two Jest workers, the existing heap limit, the 45-minute
  test-step timeout, and its own isolated MySQL setup.
- The existing `Build backend and API` required check becomes a final gate.
  It requires all prerequisite jobs to succeed and verifies that uploaded
  shard inventories cover the complete suite exactly once.
- Missing artifacts, inconsistent inventories, duplicate tests, and failed,
  cancelled, or skipped prerequisite jobs prevent the final gate from passing.
- Superseded PR runs still cancel automatically. Reruns can replace their
  shard's inventory artifact within the same workflow run.

## Backend Deployment

No services or Lambdas require redeployment. Application code, API contracts,
database schemas, fixtures, and deployment workflows are unchanged.

## Risks / Follow-Ups

The workflow uses five parallel execution jobs plus a final aggregation job.
Actual latency depends on available runner capacity; repeated installation
adds some aggregate runner work. The timing improvement must be measured on
GitHub. Database cleanup and test transformation optimizations remain outside
this PR's scope.
