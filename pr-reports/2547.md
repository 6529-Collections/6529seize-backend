# Subscriptions keyed by 6529 identity

[Backend PR #2547](https://github.com/6529-Collections/6529seize-backend/pull/2547) · [Frontend PR #5026](https://github.com/6529-Collections/6529seize-frontend/pull/5026)

## Summary

Meme subscriptions move from consolidation keys to 6529 identities: a principal on the 6529 chain, or a wallet bound to none. New `subscriptions_id_*` tables hold the same state keyed by identity, loaded from an opening file cut from the legacy tables and checked against Ethereum and the legacy tables. Until a planned switch at a real mint the legacy tables stay the truth, and with the shadow flag on every loop also writes the identity tables and compares each list, phase pull, redemption run and signed change with the legacy side. `go-live` makes the switch in one step, and only when those comparisons matched. After it, people's subscription changes come as signed records, and the legacy tables are written as the rollback copy. Every write to the identity tables is journaled to the shared record log, so the tables can be rebuilt from the opening file and the journal alone, and a verifier checks the journal's money against its inputs and Ethereum. Nothing on Ethereum changes.

## Backend impact

- New tables `subscriptions_id_*` (balances, mode, choices, final rows, uploads, logs, redemptions, top-ups, a key map, a state row, cursors and comparison reports) and `subscription_rekey_fallback_state`, created by `dbMigrationsLoop`.
- The top-up, daily and transactions loops run identity writers after their legacy work, only when the shadow flag is on and a loaded opening is not suspended, or after the switch. With every flag off nothing new runs. `delegationsLoop` and `ownersBalancesLoop` run changed shared code.
- The four subscription write routes take an `x-6529-signed-records` header with one signed record. Before the switch they behave as today; after it an unsigned change gets 409, and the web app signs (frontend PR #5026, behind its own flag).
- The CLI `subscriptions:opening` (`cut`, `verify`, `load`, `compare`, `go-live`, `status`, `suspend`, `rebuild`, `open-writes`, `verify-journal`) runs the opening, the switch, rollback and rebuilds.
- Ten new alert codes (`SUBSCRIPTIONS_*`), listed in the PR description.
- The optional re-key fallback (`FEATURE_SUBSCRIPTIONS_REKEY_ON_MIRROR`) keeps legacy keys in step when the identity mirror regroups wallets.

## Deployment

- Deploy with every flag off: `dbMigrationsLoop` first, then `api`, `subscriptionsDaily`, `subscriptionsTopUpLoop`, `transactionsProcessingLoop`, `delegationsLoop` and `ownersBalancesLoop`. Nothing changes until a flag is set.
- Then follow the staging plan in order: the record log's closer, an opening cut and loaded, `FEATURE_SUBSCRIPTIONS_SHADOW=true`, the web app's signing flag, and a rehearsed switch.
- The switch itself, `go-live --signed-writes-live`, is run by the team: Tue 1 Dec 12:00 UTC if go-live's check passes on Mon 30 Nov's minted card, otherwise 12:00 UTC the day after the next real mint.

## Rollback

- Before the switch: unset `FEATURE_SUBSCRIPTIONS_SHADOW`. The legacy tables were the truth throughout.
- After it: `subscriptions:opening -- suspend` puts every service back on the legacy tables within about 2 minutes, counting the API cache. Going forward again takes a new `go-live`, which cuts from the legacy tables.

## Tests

- MySQL: 180 tests in 9 suites (the key-width guard's two among them), covering the opening, the writers in shadow and after the switch, go-live and its gate, every rebuild case, the journal's guards, the signed write paths and the re-key fallback.
- Unit: 470 tests in 56 suites, and the 8 subscription API tests that need a database.
- Type check, lint and format checks are clean.

## Known limits

- The rebuild and the daily journal check read the journal from the records wave, and no reader for it is bound yet: until then they say so and stop. After a database restore, the runbook step (suspend, then go-live before the writers run) is the guard.
- If the database is lost before the record log's closer posts, up to 5 minutes of builds, phase pulls and choices are not in the journal. Top-ups and redemptions come back from Ethereum.
- A block of airdrops larger than one run's caps is charged in one transaction: 3,502 airdrops took 167 s in a test.
- The legacy write routes check the switch's pause before their own transactions; go-live waits 10 s after the pause to cover a write in flight.
