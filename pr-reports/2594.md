# PR Report: Rebuild check: files named by their Keccak-256 count when the chain vouches for the name

PR: [#2594](https://github.com/6529-Collections/6529seize-backend/pull/2594)
Base: the step needs PR's branch (#2569); merges after #2569

## Summary

The rebuild check's files source counted a file as verified only when its name was the SHA-256 of its bytes. The waves import reads files the chain names by Keccak-256: the Waves v1 file by the hash its import answer gives, and each wave's drop archive by its hash in the archive index, which the chain commits to only through the Waves v1 file's `dropArchiveRoot`. A files directory holding them stayed provisional, so a run using them could never count as final. A file named `keccak256-<64 lowercase hex>` now counts as verified when its bytes hash to its name and the chain vouches for the name. Nothing outside the rebuild check and its docs changes.

## What Changed

- **Keccak-named files** (`src/rebuild/sources/file-server.ts`).
  - A file named `keccak256-<64 lowercase hex>` has its Keccak-256 checked against its bytes. Other bytes fail the run, and so does any other name starting `keccak256-` in any case (capitals, an extension).
  - Such a file counts only when the chain vouches for its name. Until then it stays provisional, with the reason, and fails nothing.
- **The Waves v1 file** (`start-sources.ts`, `http-recording.ts`, `drop-archives.ts`).
  - When the sources start, the run reads the import answers from the gateway's recording. An answer counts when it is keyed as a GET of `/v1/waves/import`, answered 200 with `completed: true`, and gives `data.fileHash`.
  - Only the file named `keccak256-<that hash>` is the Waves v1 file, and it must be one (schema `0x411D`, version 1). If the answers name more than one file, none counts.
  - A Waves-shaped file under any other name vouches for nothing.
- **The archive index** (`drop-archives`, the snapshot tool's `archives/index.json`). It is accepted only when:
  - the root over its `(waveId, hash)` pairs equals that Waves v1 file's `dropArchiveRoot` (bytes 96 to 128 of its header);
  - the pairs are strictly ascending by `waveId`, so no wave appears twice;
  - its own `dropArchiveRoot`, when it gives one, is that root;
  - each entry's 6529.io wave UUID derives its `waveId` (DerivedId, domain `0x0501`).

  A fault in the index or a root that differs fails the run.

- **The archives.** An archive counts once the checked index names it, at the size (`bytes`) the index lists. An archive of another size fails the run.
- **Only from a verified gateway.** All of these count only while the gateway source is verified. A name from a gateway answer that isn't verified yet vouches for nothing, and the reason says so.
- **The root, computed in the harness** (`src/rebuild/sources/drop-archives.ts`). It follows the chain spec's definition: domain-tagged Keccak leaves, a pairwise list tree with an odd last leaf going up unchanged, and a root bound to the count. It's written from that definition, not from the code that reads the archives, so a fault in the reader can't agree with itself.
- **Test vectors** (`src/rebuild/sources/fixtures/drop-archives/`). Made-up archives and indexes of zero to three waves, computed with the snapshot tool's own encoder. No real data.
- **Docs** (`docs/rebuild-check.md`). Which file names count as verified, and how the archive index is checked.

## Backend Impact

**Deploy:** none. No Lambda, route, schema, schedule, queue or alarm changes. No loop, route or deploy imports these files.

**Live behaviour.** Unchanged.

**Other services.** None. The Keccak hashing uses the `ethers` package the backend already depends on.

None.

## Rollback

Revert the PR. Nothing in the data needs undoing. Keccak-named files then keep a files directory provisional again, as before.

## Risks / Follow-Ups

- **Merge order.** It meets #2581 (frozen gateway) in `http-recording.ts` and `start-sources.ts`. Whichever lands second makes `recordedExchanges` read the same lines the frozen check verified, the last line per key winning as in the replay, keeps the files source's `gatewayVerified` as `!gateway.info.provisional`, and adds a test that a frozen recording's import answer names the Waves v1 file.
- **Provisional until the gateway counts.** A live gateway, a recording without an import answer, or a gateway not yet verified (a plain replay, on this base) leaves the import files provisional.
- **Memory at startup.** The files source reads and hashes every file of its directory and serves them from memory. A large archive set costs memory and time at the start of a run.
- **No full-run coverage yet.** The check's own world serves no Keccak-named file, so only the unit tests exercise these paths until the waves import's files are in a run.
