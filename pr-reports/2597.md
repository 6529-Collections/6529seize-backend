# PR Report: Rebuild check: the waves import reader's files count when the chain vouches for them

PR: [#2597](https://github.com/6529-Collections/6529seize-backend/pull/2597)
Base: the Keccak files PR's branch (#2594); merges after #2594

## Summary

The waves import reader serves its files under its own ids: `waves-v1`, `drop-archives`, `drop-archive-<waveId>`, `docs-index`, and each document under its raw CID. The rebuild check's files source counted the Waves v1 file and the archives as verified only under `keccak256-<hex>` names, and knew no docs index, so a files directory laid out for the reader stayed provisional and a final run couldn't count it. The files source now verifies the reader's layout from the Waves v1 file down, beside the Keccak names. Nothing outside the rebuild check and its docs changes.

## What Changed

- **The reader's ids** (`src/rebuild/sources/file-server.ts`).
  - `waves-v1` is the Waves v1 file when its Keccak-256 is the `fileHash` of the gateway's recorded import answer. Other bytes fail the run.
  - `drop-archive-<waveId>` counts when its Keccak-256 is the hash the checked drop archive index lists for that wave, at the size the index lists. Other bytes fail the run. An archive of a wave the index doesn't list stays provisional.
  - Each document is served as `b` and the lowercase base32 of its raw CID, and its bytes must hash to its entry's Keccak-256. Other bytes fail the run.
- **The docs index** (`docs-index`, the snapshot tool's `docs/index.json`). It is accepted only when:
  - the root over its entries equals the Waves v1 file's `docsRoot` (bytes 64 to 96 of its header);
  - the entries are strictly ascending by `(docClass, ref)`, so no document appears twice;
  - its own `docsRoot`, when it gives one, is that root;
  - each entry names the raw CID its document is served under (`rawCid`). A CID document's `rawCid` is its `cid`, and the Keccak-256 of that CID must be its `ref`.
- **A set that isn't whole stays provisional.** An archive or document a checked index lists that the directory lacks keeps the source provisional, naming the file. So does a missing index when the Waves v1 file's root for it isn't the empty root.
- **Unchanged from #2594.** All of it counts only while the gateway source is verified, and stays provisional until an import answer names a served Waves v1 file. Bytes that aren't the ones a name or an answer gives fail the run as soon as they are checked.
- **The docs root, computed in the harness** (`src/rebuild/sources/wave-docs.ts`). It follows the chain spec's definition: tagged leaves over `(docClass, ref, hash)` and the same list tree as the archive root. It's written from that definition, not from the code that reads the documents.
- **Test vectors** (`src/rebuild/sources/fixtures/wave-docs/`). Three made-up documents and their index, computed with the snapshot tool's own encoder. No real data.
- **Docs** (`docs/rebuild-check.md`). The reader's ids, how the docs index is checked, and when a missing file keeps the directory provisional.

## Risks / Follow-Ups

- **#2594's behaviour changes for one layout.** A directory laid out the Keccak-named way, holding a Waves v1 file that lists documents and no `docs-index`, counted as verified on #2594. It now stays provisional, naming `docs-index` as missing. That's intended: without its documents the set isn't whole.
- **One reason's wording.** A document served under a `keccak256-<hex>` name, in a directory with no `drop-archives`, gets the reason about the archives. It stays provisional either way.
- **Not checked.** The indexes' `file`, `drops` and `nonce` fields are informative. A commitment document's `ref` is bound through the root, not recomputed from its nonce.
- **Speed and memory, unchanged from #2594.** Startup reads and hashes every file and serves them from memory. Keccak-256 runs at about 23 MB/s, so a 1.5 GB archive takes about 65 seconds.
- **No full-run coverage yet.** The check's own world serves no Waves v1 file, so the unit tests and a check of the snapshot tool's own output exercise these paths until the waves import's files are in a run.
