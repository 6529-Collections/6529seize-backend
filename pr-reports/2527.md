# PR Report: Queue the delegations loop's holdings regroupings, hourly key sweep; dumps manifest; volume windows by block time

PR: [PR #2527](https://github.com/6529-Collections/6529seize-backend/pull/2527)
Base: #2522, or `main` once #2522 merges

## Summary

From switch-on, identities and their wallets live on the 6529 chain, and the identity mirror writes `address_consolidation_keys` from it. The mirror already queues the wallets it regroups for the holdings loops, through the reconciliation queue. This PR makes the delegations loop queue its regroupings the same way, and adds an hourly sweep that catches any regrouping the loops missed. The daily open-data dumps gain a manifest that says which source and height each file reflects. The NFT volume windows count by block time, so a rebuilt `transactions` table gives the same windows. All three are behind flags that default to off.

## What Changed

- **What the flag gates.** `FEATURE_HOLDINGS_MEMBERSHIP_QUEUE` gates the delegations loop's queueing and the hourly key sweep. The identity mirror's own `queueHoldings` handler queues the wallets it regroups for `nftOwnersLoop` and `aggregatedActivityLoop` whatever the flag says, as it does on `main` today. On `main` the delegations loop's reconsolidation also takes the mirror's regrouped wallets, so with the flag on they are queued twice. That is harmless: the queue keeps one entry per wallet and loop, and at worst a loop regroups a wallet twice.
- **Key sweep** (`src/holdings/holdings-key-sweep.ts`):
  - compares each consolidated table with the keys its wallets map to: stale keys, missing keys, a wallet under two keys;
  - with the flag on, `ownersBalancesLoop` runs it with repair after the balances of the scheduled run that starts at minute 0, queuing at most 2,000 wallets per loop; a wallet already waiting keeps its place;
  - an administrator can invoke `ownersBalancesLoop` with `{"action":"holdings-key-sweep"}` (report only, with the grouped-total check) or `"repair": true` (queues even with the flag off).
- **Delegations loop:** reconsolidation regroups holdings through `regroupHoldings`: queued with the flag on, consolidated in place with it off, as today.
- **Dumps manifest** (`src/dbDumpsDaily`), behind `FEATURE_DB_DUMPS_MANIFEST`:
  - delegations and consolidations are read with the mirror's state in one REPEATABLE READ snapshot, then the transactions and the latest `nftdelegation_blocks` row;
  - `manifest.json` goes up last, with each file's key, rows, SHA-256 and source (Ethereum block, NFTDelegation block, or the mirror's `next_height` and last move);
  - while the mirror is mid-pass, before its first pass, or stopped for 30 minutes, the two chain files are skipped; their previous CSVs stay and their entries carry the previous manifest's description forward, with the reason, unless the CSV was written after that manifest;
  - the schedule stays at 01:00 UTC.
- **Volume windows** (`src/db.ts`), behind `FEATURE_ETH_INDEX_REBUILD_FIXES`: the 24 hour, 7 day and 1 month volumes count by `transaction_date` instead of `created_at`.
- **Queue helper:** `transferReconciliationDb.enqueueIfAbsent` (insert-ignore) for the sweep.

## Rollback

- **Queue:** set `FEATURE_HOLDINGS_MEMBERSHIP_QUEUE` to `false`; the sweep stops, and the delegations loop consolidates holdings itself. The mirror keeps queueing its regroupings, as on `main`. To catch up, run one reset of the three holdings loops (`NFT_OWNERS_RESET`, `ACTIVITY_RESET`, `OWNER_BALANCES_RESET`).
- **Manifest:** set `FEATURE_DB_DUMPS_MANIFEST` to `false`, then delete `db-dumps/<env>/manifest.json`.
- **Volume windows:** set `FEATURE_ETH_INDEX_REBUILD_FIXES` to `false`.

## Risks / Follow-Ups

- **Sweep cost on the writer.** Synthetic data on MySQL 8.0.46 (150,000 holders, 1,000,000 `nft_owners` rows): about 6.8 s of server time warm, 16.8 s with a 128 MB buffer pool. It runs hourly and only with the flag on; a failure is logged and doesn't fail the balances run. The staging timing above checks production's size.
- **A wallet moving between identities** can lack a consolidated row for about a minute when its old and new identities fall in different queue batches.
- **The first dump after switch-on** will likely skip the chain files; Sunday's 01:00 run is the first complete one.
- **Tests.** The MySQL tests ran on a development server; CI runs them on its own MySQL.
