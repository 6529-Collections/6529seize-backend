# PR Report: Profile sites on the chain: publish returns its two files for the browser to upload

PR: [#2568](https://github.com/6529-Collections/6529seize-backend/pull/2568)
Base: #2558's branch (the profile site area of the rebuild check); merges after #2542, #2544 and #2558

## Summary

With profile sites on the 6529 chain, publish used to put the content core and the signed publication record in the gateway's document store itself. The gateway no longer takes uploads with 6529.io's service key, and all of 6529.io's publishes would share its few egress addresses' upload budget. So the person's browser uploads the two files through the gateway's public name, as it already does for the ProfileDoc. Publish now returns both files instead of uploading them. Nothing changes while `FEATURE_PROFILE_CMS_CHAIN_POINTER` is off.

## What Changed

- **Publish with the chain flag on** records the publication as before and returns the draft with `chain_documents`: the content core and the signed publication record, each with its CID and its bytes in base64. Nothing goes to the gateway from the server.
- **Checks before anything is stored.** The content core is rebuilt from the stored package and must hash to the package hash. Each file must fit the gateway's 2 MiB upload cap, else 413 `cms_chain_document_too_large`. Both checks run before the record goes to 6529.io's storage, so neither leaves an orphan upload.
- **A recorded publication** (a second publish, or a first one when another click recorded first) returns its files again. The record comes back from the storage its recovery receipt names: 502 `cms_publication_mismatch` when storage or its CID says the bytes don't match, 503 `cms_check_unavailable` when it can't be read now.
- **The answer's size:** it keeps the package, which the schema requires, plus the core in base64. That is under 5 MB for a package at the 2 MiB storage cap, inside Lambda's 6 MB.
- **`putDocBytes` leaves `ProfileCmsChainPort`,** the test chain and the rebuild check's flag-off port. 502 `cms_doc_store_mismatch` goes.
- **OpenAPI:** `chain_documents` and its two schemas, and publish's 413, 502 and 503. The models are regenerated with the pinned generator. The docs describe the browser's upload.

## Backend Impact

**Deploy:** `api` only. No new route, table, column, loop or schedule.

**Live behaviour.** Unchanged while the chain flag is off. The flag stays off until this PR and the frontend half are both deployed.

**Other services.** None.
