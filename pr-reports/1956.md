# PR Report: Attribute Desktop release notes to their publisher

PR: https://github.com/6529-Collections/6529seize-backend/pull/1956
Branch: agent-prxt/desktop-release-attribution -> main
Related PRs: https://github.com/6529-Collections/6529-core/pull/231

## Summary

Desktop release notes now support both production publishing flows and identify the person who published the release with a real 6529 mention when their GitHub account is mapped.

## What Changed

- Accept `Publish` and `Build All` as valid Core production release workflows.
- Require the queued workflow metadata to match the current GitHub Actions run while selecting the previous release across either supported flow.
- Add a general `Published by @[handle]` footer to Desktop release notes.
- Omit publisher attribution when the triggering GitHub login has no configured, resolvable 6529 profile.

## Backend Impact

- New services: None.
- Changed services: `releaseNotesGenerationLoop`.
- Required service order: `releaseNotesGenerationLoop` only.
- API: No deployment required. The existing CI pipeline alert receiver already forwards the selected Core flow and triggering GitHub login into release-note generation.
- DB/entities/migrations: None.
- Queues/events/integrations: The existing release-note generation queue payload is unchanged; its existing workflow and actor fields are now consumed by Desktop publication.

## Config / Env

No new configuration or environment variables. Publisher mentions use the existing versioned GitHub-to-6529 handle mapping and identity lookup.

## Release Notes

Production Desktop releases created through either Publish-only or Build All now produce the same release-note behavior and credit the publisher once at the note level.
