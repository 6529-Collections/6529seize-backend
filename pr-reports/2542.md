# Rebuild check: prove that MySQL holds only an index

[Backend PR #2542](https://github.com/6529-Collections/6529seize-backend/pull/2542)

## Summary

`6529 run rebuild:check` checks, on a developer's machine, that 6529.io's MySQL database can be rebuilt from public sources. It starts a private MySQL server, builds the schema from code, writes a small fixture through each area's seed (the identity profiles with plain SQL until identity has a rebuilder), and asks the API a set of questions. Then it drops every table except sessions, queues, cursors and provider caches, rebuilds the rest from the 6529 chain, the relays, Ethereum and content-addressed files, and asks again. Every answer must match the first one; in a final run the rebuilt rows must match too.

Every table the code names is in one area's manifest with a class (INDEX, EPHEMERAL, PROVIDER, SCHEMA, VIEW, RETIRED or EXEMPT). A unit test fails when a new table has none. Until this PR merges, any new table on main needs its manifest line before or with the merge.

Nothing in production changes, and there is nothing to deploy.

## What a pass shows today

- The check runs end to end: schema, seeds, both sets of answers, the drop, the rebuilders under their source guard and their own MySQL users, and the comparison.
- Rebuilt areas answer the same after the drop as before it.

It does not yet show that every table except the EXEMPT ones rebuilds. The report lists what is still open on every run:

- **Pending tables:** INDEX tables without a rebuilder are kept, not rebuilt. Most areas' rebuilders are in their own PRs.
- **Unproven probes:** a question answered with a 4xx, or with an empty, non-JSON or data-free 2xx, proves nothing (it still fails if the second answer differs). Areas add seeds so their questions find data.
- **Rebuilt tables with no rows after the seeds** prove nothing either.
- **Tables a fresh schema lacks:** `artists`, `meme_lab_royalties` and `ratings_snapshots` have no table on a fresh database. The three questions that read the first two are held until the holdings PR adds those entities, so a full run on this PR alone passes. `ratings_snapshots` needs one line in `src/entities/entities.ts`.
- **Planned steps:** seeds and rebuilders that live in other areas' PRs are skipped on this PR alone, and their tables kept.

`--final` fails on all of these, on provisional sources (live URLs, hand-written recordings, the local relay) and on rebuilt rows that differ. A final run is the proof that every table except the EXEMPT ones is an index.

## How the team runs it

```text
6529 run rebuild:check -- --home .rebuild/full --source ethereum=anvil --source relays=relay --source files=<dir>
```

It needs a MySQL 8.0 server binary and Foundry's `anvil`. `--area <name>` checks one area. `docs/rebuild-check.md` has the manifest format, the sources and the report.

## Backend impact

- No tables, migrations, loops or API changes.
- An optional `ALCHEMY_BASE_URL` override, unset everywhere it is deployed, and an exported `saveTeam` in the team loop.

## Risks and follow-ups

- The check doesn't run in CI yet; a job needs MySQL 8.0 and `anvil` on the runner.
- Areas add their rebuilders and seeds in their own PRs.
