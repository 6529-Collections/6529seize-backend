# Backend ordinary Ethereum RPC portability

PR: [#1979](https://github.com/6529-Collections/6529seize-backend/pull/1979)

## Issue

Ordinary backend reads still derived Alchemy URLs from `ALCHEMY_API_KEY`,
even after the additive configuration/provider foundation merged in #1985.
The original documentation-only #1979 now implements the remaining migration,
at the user's request, rather than creating more implementation PRs.

## Changes

Blocks, logs, transactions, receipts, ENS, code and contract reads now use
`ETHEREUM_RPC_URL` through the shared provider-neutral boundary. Mixed NFT,
NextGen and subscription indexing retains Alchemy indexed APIs but sends
ordinary reads through that boundary. Retry, result-shape, pagination and
checkpoint contracts are preserved. Marketplace capability checks now require
the RPC URL instead of the Alchemy key; bounded raw preflight verifies mainnet.

Neutral types and standard compatibility methods move out of the local Alchemy
module. Hard-coded ordinary ENS fallback routing and Alchemy-derived ordinary
URL helpers are removed. Non-standard transaction tracing has an explicit
separate provider policy, preserving Alchemy and existing 6529-first fallback
behavior without redirecting ordinary transaction/receipt reads.
NextGen admin-validation failures log only allowlisted diagnostic codes, never
raw provider messages or credential-bearing URLs, while continuing to deny access.

The canonical [portability record](../docs/ethereum-rpc-provider-portability.md)
and [architecture](../docs/architecture.md) describe the implemented boundary.
The historical foundation record is marked as superseded for caller routing.

## Configuration and retained boundaries

- `ETHEREUM_RPC_URL` is now required when these callers execute. Start with
  the Alchemy mainnet URL; a later qualified provider change needs configuration
  plus service restart/redeploy, not application changes.
- The existing regional Secrets Manager `prod/lambdas` loader supplies runtime
  values. API requires `API_LOAD_SECRETS=true` for that route, or its existing
  alternative runtime configuration. No new Actions secret wiring is needed.
- Sepolia/Goerli paths require their corresponding explicit RPC URL only when
  used; unsupported chains never fall back to mainnet.
  Before rollout, verify effective `NEXTGEN_CHAIN_ID` (unset/empty, `1`,
  `11155111`, or legacy `5`) and `SUBSCRIPTIONS_CHAIN_ID` (unset/empty, `1`, or
  `11155111`) in staging and production. Previously tolerated unsupported or
  malformed values now fail closed; deployed values have not been checked here.
- Keep `ALCHEMY_API_KEY` for NFT REST, indexed transfers and Alchemy tracing.
  `NFT_INDEXER_RPC` remains a separate bulk-indexing/NFT-link capacity boundary.
  The legacy AWS Managed Blockchain `/rpc` surface remains unchanged.
- The user reported provisioning mainnet URLs in staging and production.
  Deployed configuration and endpoint capability have not been verified here.

## Risk and rollback

Medium rollout risk with a broad shared-provider surface: API features and
multiple indexers change routing. Live staging verification of ENS, contract-wallet signatures,
marketplace preflight, indexing progress and trace-derived values remains
required. Trace failures preserve existing incomplete-attribution behavior;
generic JSON-RPC support does not imply trace support.
Verify retained trace credentials and compare reverse ENS coverage against a
pre-deploy wallet sample during the ENS-loop rollout. A missing Alchemy key can
silently reduce trace attribution, and removal of the hidden 6529 ENS fallback
can yield more null names without failing a worker invocation.
Marketplace reads intentionally retain chain verification rather than trusting
the configured URL via `staticNetwork`; compare read/simulation latency during
staging because the additional chain checks can add RPC traffic and latency.

No schema, API contract, dependency, queue or deployment-workflow change.
Restore the previous URL and restart services to roll back an endpoint change,
or redeploy previous artifacts with their old credentials intact to roll back
the migration. Do not remove the URL while migrated code is running.
