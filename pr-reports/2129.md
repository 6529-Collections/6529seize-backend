# PR Report: Drop metadata publication timestamps

PR: https://github.com/6529-Collections/6529seize-backend/pull/2129
Branch: `agent-prxt/drop-schema-date-fix` -> `main`
Related PR: [Frontend #4137](https://github.com/6529-Collections/6529seize-frontend/pull/4137)

## Summary

Drop metadata now exposes its original publication time for both CHAT and SUBMISSION, allowing the frontend to provide a genuine `datePublished` in Wave drop structured data. Previously, `submitted_at` was null for chats.

## What Changed

- Add optional `created_at` in Unix milliseconds, mapped directly from the existing visible drop.
- Preserve `submitted_at` as the original creation time for submissions and null for chats; winner decision time remains separate.
- Regenerate the API model and serializer and document the timestamp semantics.
- Keep the existing visibility and moderation lookups authoritative; no new data fetch bypass is introduced.

## Backend Impact

Only `api` changes. No new service, database/entity/migration, queue, configuration or environment changes. System architecture is unchanged; no architecture-doc update is needed.

## Backend Deployment

Planned, not deployed by request: deploy `api` before the related frontend consumer. No other backend service is required.

## Risks / Follow-Ups

The local installation lacks `ws` type declarations, leaving root type-check errors in unchanged WebSocket code. The focused metadata suite uses a temporary DB-free configuration with only that missing-declaration diagnostic excluded; no repository harness or dependency changes are included.
