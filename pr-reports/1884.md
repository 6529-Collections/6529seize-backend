# PR Report: Fix npm lockfile and enforce pinned Corepack installs

PR: https://github.com/6529-Collections/6529seize-backend/pull/1884
Branch: `agent-prxt/fix-npm-lockfile-tooling` -> `main`
Related PRs: None

## Summary

Repairs the npm lockfile, updates vulnerable or incompatible dependency paths,
and makes the repository-local `6529` command the enforced entry point for npm
installs, scripts, and package binaries. The repository pins `npm@10.9.8`
through Corepack behind that wrapper.

## What Changed

- Completed missing optional-native lockfile records and updated the affected
  dependency graph and compatibility overrides.
- Added the repository-local `6529` command, shell bootstrap support, direct
  npm/Corepack/npx rejection shims, and package-manifest enforcement.
- Pinned and guarded every package root, including packages below
  `src/api-serverless`, and routed nested package operations through `6529`.
- Added focused tests for lockfile completeness, wrapper behavior, missing
  package guards, direct nested package-manager commands, and CI contracts.
- Updated developer, workflow, agent, skill, and API generation guidance to use
  the wrapper consistently.

rollout rather than being added after validation.
