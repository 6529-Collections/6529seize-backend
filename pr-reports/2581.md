# PR Report: Rebuild check: a gateway recording made through the frozen-snapshot node can count

PR: [#2581](https://github.com/6529-Collections/6529seize-backend/pull/2581)
Base: the column owners PR's branch (#2577); merges after #2569 and #2577

## Summary

A gateway recording used to stay provisional, because nothing checked its answers. A recording made through the validator's frozen-snapshot API node (`validator run --api-frozen-snapshot`) can now be checked end to end, and when every check passes it counts for `--final`. The checks: the header ties each snapshot to its height, roots and the hash of the kept data-dir copy; at least two other live nodes reported the same roots; and the run re-serves each copy and replays every answer to the same bytes. Nothing outside the rebuild check and its docs changes.

## What Changed

- **Header checks** (`src/rebuild/sources/frozen-gateway.ts`).
  - Each snapshot needs a plain phase name, its option, a height, a block root, an app state root, the copy's SHA-256, its archive named by that hash with the archive's own SHA-256, and the copied node.
  - At least two distinct live nodes other than the copied one must report the snapshot's height and both roots.
  - The header names the build: the full `validatorCommit`, the Linux binary's hash and the Windows binary's hash. A Windows build from another commit names that commit in full.
  - Every recorded line names a snapshot and is keyed by exactly its own method, path and body. Its path starts with `/`, has at most one `?`, and has query names made only of letters, digits, `_`, `.` and `-`, each once. No two lines share a key, and the answer counts must add up.
- **Re-serve and replay**, with `--validator-bin <file>` and `--frozen-port <n>` (1024 to 65535).
  - The binary's hash must be the header's for this platform, and its `run --help` must list the frozen option.
  - `devnet.toml` must be there and match the header's hash. Each archive is checked, unpacked into the run's own work folder by position, and checked again. The tar reader (`tar-reader.ts`) refuses links and names that climb out.
  - The node serves on 127.0.0.1 on the given port only (`frozen-config.ts`). A config that names a peer is refused.
  - One frozen node runs at a time (`frozen-guard.ts`). The lock holds while the run or the node lives.
  - The node is stopped through its own child handle, never by name. Only its `close` counts as its end.
  - `/v1/status` must name the snapshot's height and roots. Then every answer is replayed and must come back with the recorded status, content type and bytes.
- **Final only for the reviewed build.** `--frozen-reviewed <commit>@<sha256>` must name the header's commit and the replay binary's hash before a passing recording counts as final.
- **Report** (`report/report.ts`, `sources/http-recording.ts`).
  - A failed check fails the run and names the check.
  - A recording the run can't re-serve, or whose build isn't named as reviewed, stays provisional with the reason.
  - Answers tagged after the capture (`retagged`), and answers listed as `notReplayable` with the fields a second serving can't repeat, keep it provisional. A listed answer is still replayed with those fields left out.
  - A frozen recording can't be recorded into, and errors quote local folders by label, not by path.
- **Request keys** (`sources/exchange-key.ts`). The key helpers move to one module the recording and the checks share. The query sorts in code-unit order, so a key is the same on every machine. No recorded line changes key.
- **CLI** (`cli.ts`). The three options, with a port outside 1024 to 65535 and a build not in full refused.
- **Docs** (`docs/rebuild-check.md`). The three checks, the lists and the options.

## Backend Impact

**Deploy:** none. No Lambda, route, schema, schedule, queue or alarm changes. No loop, route or deploy imports these files.

**Live behaviour.** Unchanged.

**Other services.** None. The check runs the validator binary locally, on 127.0.0.1, only when a run is given one.

## Config / Env

None.

## Rollback

Revert the PR. Nothing in the data needs undoing. Recordings without a `frozen` header stay provisional, as before.

## Risks / Follow-Ups

- **Merge order.** It meets #2559 (relay recordings) in `start-sources.ts` and in the runner's `startSources` call. Whichever lands second adds `frozen?: FrozenOptions` to #2559's `SourceOptions`.
- **Windows build.** The re-serve needs the Windows build of the capture's commit on the machine that runs the check. Without it, frozen recordings stay provisional, with the reason.
- **Coverage.** The replay covers what the recording holds. A request the run makes that the capture didn't record still fails the run.
- **Untested paths.** SIGKILL after the timeout, and the stop on exit or Ctrl-C. On Windows a SIGTERM already ends the process.
- **Stop without a time limit.** After the SIGKILL, the stop waits for the node's `close`. A grandchild holding the node's output open could keep it waiting, with the lock held. The frozen node starts no child process.
