# Mint log: every minting write as a signed, replayable entry

[Backend PR #2536](https://github.com/6529-Collections/6529seize-backend/pull/2536)

## Summary

Every write to the minting tables (distributions, allowlists and merkle trees, photos, claims, card mappings, NextGen allowlists, collaborations, rememes, and the published rememes and royalties files) becomes one entry in the shared record log. An entry names who asked, with their signed record or wallet signature, and the exact rows the write changed. The tables can be rebuilt from empty, from genesis files and the entries, through the code that checked each live write.

The rememes file loop stops deleting rememes added on the site, and the team's pre-vote artist badges load from a file in the repo. This PR also adds a `memes_mint_stats` rebuild for the rebuild check (`writeClosedMemesMintStats`, the NFT loop's writer for every closed mint); nothing in production calls it.

Every behaviour is behind a flag that is off by default; rollback for each is to set it to false. #2523 and #2526 are merged into main; deploy them before this PR. #2526 adds `recordOwnerDirectory`, which the API binding takes.

## Backend impact

- **New tables** (additive, entity sync): `mint_log_head`, `mint_log_card_heads`, the last entry of each sequence. Losing a row breaks its sequence; a rebuild or a new genesis restores it.
- **Changed functions:** `api`, `claimsBuilder`, `claimsMediaArweaveUploader`, `waveDecisionExecutionLoop` (the freeze at mint selection), `rememesLoop`, `royaltiesLoop`, `teamLoop`. No route or response changes; the NextGen allowlist upload accepts one optional field, `allowlist_sha256`.
- **Connections:** each logged write holds two database connections (the log's transaction and the writer's own); size the pools for twice the concurrent minting writes. Collaboration writes hold one.
- **Flags:**
  - `FEATURE_MINT_LOG_SHADOW`: logging failures are alerted and the write goes ahead. The exception is a deadlock that MySQL resolves against a drop write or decision carrying a collaboration write: that write fails and can be retried.
  - `FEATURE_MINT_LOG_REPLAY_CHECK`: replay each entry in a savepoint and compare.
  - `FEATURE_MINT_LOG_PRIMARY`: not usable until the principal bindings (`setMintPrincipalBindings(recordOwnerDirectory)`, which reads a wallet's binding history from the chain gateway) and the site's principal source land. Turned on now, it refuses every admin minting write from the site (400 `INVALID_SIGNED_RECORD`); NextGen uploads and service writes are not refused.
  - `FEATURE_MINT_LOG_COLLAB_RECORDS`: collaboration invites and replies keep shadow rules until most artists have enrolled a device grant; the team decides when.
  - `FEATURE_NEXTGEN_ALLOWLIST_SIGNED_FILE`, `FEATURE_REMEMES_KEEP_ADDED`, `FEATURE_MINT_HAND_LISTS`.

## Known limits

- The genesis holds the lock through its IPFS uploads.
- Distribution photos are logged as S3 URLs, without an IPFS or Arweave copy.
- Records are checked without a live window, and a reused event id is not refused.
- The rebuild test copies the inline `GET /rememes_uploads` handler from `app.ts`.
