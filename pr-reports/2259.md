# PR Report: Claim metadata history events

PR: https://github.com/6529-Collections/6529seize-backend/pull/2259
Branch: agent-prxt/nft-history-claim-events -> main

## Summary

Record Meme metadata edits from authorized wallets independently of the legacy deployer address. Meme #550's missing October edits are the motivating incident; the permanent ingestion fix is separate from historical recovery execution.

## What Changed

- Discover finalized Manifold claim events and resolve NFT IDs through creator-scoped stored mappings verified against the emitting extension.
- Store event identity in an additive table while preserving the legacy history table, Mint, and repeated URIs.
- Handle removed metadata objects and reconcile the next recorded edit when inserting older history.
- Retain unchanged-URI claim settings updates as audit records outside Timeline; stop failed windows from advancing their checkpoint.

## Backend Impact

- Changed services: `dbMigrationsLoop`, `api`, `nftHistoryLoop`.
- Required service order: create `nfts_history_events` through the explicit `nft-history-events` schema scope, then update the API reader, then the event ingester.
- API: history response fields remain unchanged; legacy and event history are combined with transaction-level deduplication.
- DB: one additive event entity; no legacy primary-key rewrite or data deletion.
- Integration: finalized Ethereum event logs and historical mapping reads.

## Risks / Follow-Ups

- Historical repair requires the separately reviewed replay tooling and explicit execution authorization.
- MySQL integration and staging runtime validation remain required before rollout.
- Forwarded execution, unsupported protocols/emitters, missing baselines, and mapping ambiguity surface as explicit failures. Resolve those audit findings before treating a historical range as complete.
