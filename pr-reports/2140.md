# PR Report: Chat video previews

PR: [Backend #2140](https://github.com/6529-Collections/6529seize-backend/pull/2140)
Branch: `agent-prxt/chat-video-thumbnails` → `main`
Related PRs: [Frontend #4178](https://github.com/6529-Collections/6529seize-frontend/pull/4178)

## Summary

Generate a small still image during video conversion so chat can display a preview without fetching or decoding video before Play.

## What Changed

- Read and expand the existing MediaConvert template, preserving its input/audio selectors except for forcing `VideoSelector.Rotate` to `AUTO`, and retaining its HLS/MP4 outputs. Append up to two JPEG captures, at the first frame and one second, with proportions bounded to 640 × 640 pixels, quality 80.
- Explicitly bind the two captures at one frame per second to the frontend's preferred sequence-1 key; sub-second clips retain sequence-0 fallback.
- Publish `renditions/drops/<author>/<name>/poster/<name>_poster.0000001.jpg` beside existing video renditions. The frontend derives this URL from the original upload URL and falls back to sequence 0 for existing/sub-second clips.
- Grant the existing Lambda role template-scoped `mediaconvert:GetJobTemplate`, in the configured bucket/MediaConvert region. Update the function after the policy exists. The shared job template is unchanged.
- Preserve S3 trigger and video extension filtering. No automatic old-video enumeration or replay.
- Reject duplicate or empty template output groups before submission. Retain stack-configured template/bucket/region through secret loading and warm invocations, and reuse a stable event token for immediate submission retries.

## Backend Impact

- New services: None.

- API, DB, migrations, new queues/events: None.
- Integration: MediaConvert emits an additional JPEG into the existing public bucket/CloudFront path. Existing video renditions remain in the same job.

## Release Notes

New video uploads receive a preview after processing. Existing uploads do not receive thumbnails merely by deploying this code. A separately authorized replay can regenerate a selected old video's entire conversion, replacing its HLS/MP4 renditions and incurring conversion cost. No backfill was run.

## Risks / Follow-Ups

The existing shared Lambda role gains read access to this one template. The converter remains a shared-media, staging-only service under the current deployment catalog. MediaConvert's token deduplication lasts one minute; later event redelivery remains possible. Any separately authorized backfill must protect existing renditions because replacement is not atomic.

The one-second capture avoids a black opening frame when content is visible by one second. Clips still black at that point can still have a black preview; already-generated black first-frame previews are not replaced automatically. Before release, verify a real conversion, JPEG delivery, retained video renditions, and a rotated/portrait source with the account's configured AWS template and IAM permissions. Live AWS access was unavailable during implementation. Full root type checking was limited by the local API dependency installation missing declared WebSocket types; focused converter validation and packaging completed. See [the preview runbook](../docs/chat-video-previews.md).
