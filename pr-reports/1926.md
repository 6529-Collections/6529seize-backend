# PR Report: Add wallet distribution allocations API

PR: https://github.com/6529-Collections/6529seize-backend/pull/1926
Branch: `agent-prxt/home-wallet-allocations` -> `main`
Related PRs: [Frontend PR #3736](https://github.com/6529-Collections/6529seize-frontend/pull/3736)

## Summary

The API can now report a wallet's mint allocation for one card together with
whether that card's distribution has been published.

## What Changed

- Added a public wallet-allocation endpoint for Phase 0, Phase 1, Phase 2, and
  Public.
- Aggregated airdrop and allowlist spots independently and omitted zero-only
  phases.
- Reused each wallet's normalized distribution allowlist instead of rebuilding
  phase allocations from raw distribution rows. The normalized row is keyed by
  contract, card, and wallet, and the normalizer builds its allowlist from that
  wallet's raw rows only. Reads remain case-insensitive for compatibility with
  legacy or backfilled rows.
- Normalized observed phase aliases (`P0`, `Phase0`, and `Phase 0`, with the
  equivalent Phase 1/2 forms) into the canonical API phase labels.
- Derived Public airdrops from finalized subscription rows and fixed Public
  allowlist spots at zero, summing finalized subscribed quantities.
- Returned distribution publication state separately from wallet allocation so
  clients can distinguish unpublished from published-with-no-match.
- Added the OpenAPI contract, generated route and models, address validation,
  deterministic ordering, a 60-second response cache, and focused coverage,
  including a contract test that feeds the production normalizer's serialized
  wallet output into the allocation reader. The shared cache key uses the full
  request URL, including the wallet query parameter.

## Backend Impact

- API: Adds a read-only public endpoint under `/distributions`.
- Database: Read-only queries against existing distribution and finalized
  subscription tables; no migration or data mutation.
- Compatibility: Existing endpoints and response shapes are unchanged.
