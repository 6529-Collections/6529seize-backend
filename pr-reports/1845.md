# PR Report: Keep release notes complete and resilient

Related PRs: None

## Summary

Backend release notes now credit every human contributor associated with each pull request and keep publishing when optional GitHub enrichment or AI-generated summaries are unavailable.

## What Changed

- Carries optional canonical contributor GitHub logins from production CI alerts through the release-note queue.
- Builds deterministic PR contributor lists from the PR author, Release Train metadata, and GitHub-authenticated commit authors and committers.
- Excludes bot and GitHub App identities and deduplicates contributors case-insensitively.
- Renders mapped contributors as real 6529 mentions with mention metadata and leaves unmapped contributors as GitHub profile links.
- Uses bounded PR commit retrieval as the contributor fallback for manual production releases.
- Treats changed-file and commit lookups as bounded, best-effort enrichment so one unusually large or temporarily unavailable pull request cannot discard the entire release.
- Falls back to sanitized pull request titles when summary generation fails or returns incomplete output.

## Release Notes

Production release notes will retain Release Train contributor attribution and include additional human authors or committers from the associated pull request. Large pull requests no longer block the entire release-note batch, and pull request titles provide a minimum viable summary if richer generation fails. Existing grouping, service links, publication deduplication, deployment behavior, and previously published notes are unchanged.

After deployment, the failed release-note generation message can be redriven from the release-note generation dead-letter queue to recover the affected frontend release batch.
