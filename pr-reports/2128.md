# PR Report: Operational alert causes and recovery state

Branch: agent-prxt/operational-alert-context -> main
Related PRs: None

## Summary

Application alerts now show an allowlisted failure cause and explicit retry state. Amber is reserved for a verified pending attempt; red covers unknown, terminal, and exhausted outcomes. Existing green infrastructure recovery remains intact.

## What Changed

- The shared logger producer emits fixed diagnostic categories, operation, provider/status, safe resource identity, and retry state without copying exception text, URLs, headers, bodies, or arbitrary fields. The monitoring parser reconstructs that allowlist.
- The formatter puts cause, affected resource, and retry information ahead of event hashes. Generic fingerprints are grouped separately when validated cause or retry state differs; legacy queued events retain their existing key shape.
- The NFT refresher emits amber after a retry wait completes and another attempt remains. A required canonical-page 404 exits its immediate retry loop after one attempt; its persisted backoff is only demand-driven eligibility. That alert is red and explicitly says no attempt is scheduled.
- WebSocket HTTP status and completed SDK attempt count are carried from the existing bounded send diagnostic. An SDK HTTP 429 after three attempts stays red unless a delivery owner independently confirms a pending retry.

## Release Notes

Operators see amber for confirmed remaining automatic retries and red for failures requiring investigation. A retry count inside an SDK is shown as completed SDK work, not as proof of future delivery. Older queued alerts still render red with unknown recovery.

## Risks / Follow-Ups

- Retry classification is explicit only for the NFT refresher path in this change. Other service-specific retry owners need targeted annotations before they can safely emit amber. A successful Lambda invocation does not prove item recovery.
- Generic logger calls without a recognized status or condition still show their component and an unclassified cause. Raw messages remain excluded for privacy; targeted allowlisted diagnostics can improve those paths later.
- Root TypeScript and default Jest paths in this checkout encounter existing missing backend declarations/packages. Focused producer, NFT, and monitoring tests passed; NFT Jest used diagnostics disabled for that dependency issue.
- Incident deduplication beyond existing five-minute groups and automatic item recovery tracking are separate work.
