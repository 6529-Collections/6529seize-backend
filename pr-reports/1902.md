# PR Report: Add Reliable Cross-Device DM Unread Synchronization

PR: https://github.com/6529-Collections/6529seize-backend/pull/1902
Branch: `agent-prxt/dm-unread-sync` -> `main`
Related PRs: [frontend PR #3609](https://github.com/6529-Collections/6529seize-frontend/pull/3609)

## Summary

Adds an authoritative, profile-scoped DM unread contract with serial ordering and cross-session WebSocket synchronization.

## What Changed

- Added per-conversation DM unread snapshots on an explicit snapshot endpoint while retaining the existing lightweight aggregate `count` endpoint for compatibility and old-client polling load.
- Added monotonic serial read positions and state versions to wave reader metrics, including safe initialization from legacy timestamp-only state.
- Made legacy timestamp initialization and monotonic serial advancement one atomic writer-pool upsert, and forces mark-unread writes through the writer pool before authoritative rereads.
- Added explicit read-through serial support and an authoritative DM state response to the wave read endpoint.
- Broadcasts recipient-scoped unread state after new messages, permanent deletions, reads, mark-unread actions, and identity mute changes persist.
- Filters permanent-deletion broadcasts through current DM, wave, and parent visibility membership before updating reader versions.
- Paginates identity mute and unmute synchronization until every affected DM conversation has been updated.
- Keeps ordinary-wave drop creation on its existing query path; DM-only rereads and unread-version updates do not add work to non-DM drops.
- Enforces DM visibility membership before read or mark-unread state can be mutated.
- Targets every WebSocket connection synchronized for the affected profile without exposing another connected profile's state.
- Preserved ordinary-wave timestamp reads, muted-wave filtering, identity-mute filtering, and general notification invalidations.

## Backend Impact

- Changed services: `dbMigrationsLoop`, `api`
- Planned/deployed services: Both changed services are planned; neither was deployed by this task.
- API: Adds `/dm-drops/unread/snapshot` for authoritative synchronization while preserving `/dm-drops/unread` as the legacy lightweight count contract; extends wave reads while retaining body-less calls.
- DB/entities/migrations: Adds `latest_read_serial_no` and `unread_state_version` to `wave_reader_metrics` through entity synchronization.
- Queues/events/integrations: Adds the profile-scoped `DM_UNREAD_STATE_CHANGED` WebSocket event.
- Architecture: DM unread state is now one versioned backend authority consumed by all frontend surfaces.
