# PR Report: Rebuild check: steps that wait for a table, seed order, shared tables, and sources never final on their label

PR: [#2569](https://github.com/6529-Collections/6529seize-backend/pull/2569)
Base: #2542's branch; lands in #2542's branch, which merges to main

## Summary

Changes to the rebuild check (#2542), each its own commit, so areas whose data crosses others' can be rebuilt and checked without editing each other's manifests:

- a step can wait for a table another branch creates;
- a source never counts as final on its label alone;
- seeds can run last, and a step can run before another area's;
- a checkpoint table compares only its newest row;
- rebuilders of different areas can share a table by partition;
- files named by their own SHA-256 count as verified;
- a step is told whether the run is final, and an unknown step in `before` is named as such.

Nothing outside the rebuild check and its docs changes.

## What Changed

- **`needs` on steps** (`src/rebuild/manifest.types.ts`, `run/runner.ts`, `run/verdict.ts`, `registry-check.ts`):
  - A seed or rebuilder declares `needs: [{ table, reason }]`. While a needed table isn't in the run's schema, the run skips the step as planned and names the step, the table and the reason. A normal run notes it; `--final` fails on it.
  - A step may wait for any INDEX, EPHEMERAL, PROVIDER or EXEMPT table a manifest declares. One the schema already has is noted as a need to drop, and fails `--final`. The registry refuses a table no manifest declares, one of another class, and a needed table without a reason.
- **Never final on a label** (`sources/http-recording.ts`, `sources/file-server.ts`, `report/report.ts`):
  - Gateway and ethereum recordings are provisional, "answers not verified". A files directory from outside the run is provisional, "ids not verified", while it holds a file whose name isn't the SHA-256 of its bytes; a file with other bytes than its name says fails the run.
  - The seeds' own files and anvil from a state file still count.
- **`last` and `before`** (`step-order.ts`, `registry-check.ts`):
  - A seed with `last: true` runs after every other seed, so a chain indexer can catch up on blocks other seeds mined.
  - `before: [ids]` mirrors `after`.
  - The registry refuses unknown ids, cycles across both, `last` on a rebuilder, and any order that would put a seed that isn't last after a last one.
- **`checkpoint` on INDEX tables** (`snapshot/table-snapshot.ts`, `stack/mysql-admin.ts`):
  - The row diff compares only the rows holding the column's largest value, taken in SQL with MAX.
  - It is one newest row for the whole table.
  - A run fails when the column is missing or may hold NULL.
- **Partitioned writers** (`step-writes.ts`, `registry-check.ts`, `run/runner.ts`, `stack/mysql-admin.ts`):
  - A rebuilder may write `{ table, partition: { columns, values, reason } }` of any area's INDEX table.
  - Several writers are allowed only when all declare partitions on the same columns with disjoint tuples. The registry's comparison is an early warning. Before the seeds, the run compares every cross-writer pair in MySQL, through temporary copies of the table's columns with their types and collations.
  - A rebuilder that changes a row outside its partition fails the run.
  - Rows in no writer's partition are noted, and fail `--final`.
  - An area run rebuilds only its own partitions of a shared table.
- **The final flag for steps** (`run/step-context.ts`): every step's context says whether the run is final, so a seed can refuse a stand-in a final run must not count.
- **Docs** (`docs/rebuild-check.md`): all of these.

## Risks / Follow-Ups

- **Merge order.** This PR and #2559 (relay recordings) both touch `src/rebuild/run/runner.ts` and `src/rebuild/registry-check.ts`; whichever lands second adapts to the other. If this PR lands second, its never-on-a-label rule also replaces `isProvisional`, which #2559 leaves in `file-server.ts` and `http-recording.ts`.
- **Final runs.** Until a recording's answers or a directory's ids are checked against the node's proofs, a `--final` run that uses a gateway or ethereum recording, or an outside files directory, fails on it. Checking the proofs is a separate change.
- **Cross-area names.** `before` and `after` across areas still name another area's step. The registry could later order rebuilders from their declared reads and writes instead.
