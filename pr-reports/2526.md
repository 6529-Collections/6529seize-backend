# Signed records follow-up: rule refusals, owners of wallets, one chain wiring call

[Backend PR #2526](https://github.com/6529-Collections/6529seize-backend/pull/2526) · [Frontend PR #4997](https://github.com/6529-Collections/6529seize-frontend/pull/4997) · stacked on #2523

## Summary

What the signed records module's first callers need:
- a handler can refuse a change under today's rules (`RecordRuleError`, outcome `refused` with the rule's code);
- a refused record leaves nothing behind inside a caller's transaction (a savepoint);
- one owner rule for every feature: a wallet writes as the principal it is bound to on the chain, or as itself while bound to none, read from the chain's binding history;
- `GET /signed-records/owners` answers that rule for clients;
- `wireSignedRecordsChain(chainGatewayClient)` wires the gateway client into the anchor and the owners with one call.

Nothing calls the indexer yet.

## Backend impact

- **New endpoint** `GET /signed-records/owners` (no auth, 1 to 50 wallets). It answers **503 `OWNERS_UNAVAILABLE`** while the gateway client isn't wired in or doesn't answer.
- **No new tables, loops or environment variables.** No existing route changes.

## Backend deployment

1. `api`, before the frontend follow-up.
2. Later, the PR that brings the gateway client calls `wireSignedRecordsChain(chainGatewayClient)` at startup. That client needs `getHead`, `getMembershipWalletHistory` (`GET /v1/membership/wallets/{address}/history`), `getIdentityByWallet`, `getIdentityByPrincipal` and, optionally, `getIdentitiesByWallets`.

**Until then:** the anchor endpoint answers 503 `ANCHOR_UNAVAILABLE`, the owners endpoint 503 `OWNERS_UNAVAILABLE`, and every wallet counts as unbound.

**Rollback:** redeploy the previous `api`. The endpoint is additive.

## Known limits

- **A briefly stale gateway read** can fail a fresh submit with a 500 until the gateway's head moves past the record's anchor.
- **A gateway feed that no longer reaches back** to a record's anchor stops a rebuild with "does not cover height", rather than call a bound wallet unbound.

## Tests

14 unit suites (106 tests) and the heads DB suite (6 tests) pass, including a rule refusal inside a transaction the caller commits and a failed rollback with a fake executor. `tsc` and ESLint are clean.
