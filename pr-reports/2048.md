# PR Report: Subscription cutoff status

PR: [#2048](https://github.com/6529-Collections/6529seize-backend/pull/2048)
Branch: `agent-prxt/subscription-cutoff-status` → `main`
Related PR: [Frontend #4009](https://github.com/6529-Collections/6529seize-frontend/pull/4009)

## Summary

Enabling Automatic subscriptions or processing a first top-up after the mint-day
cutoff no longer makes today's unreleased card appear subscribed when there is
no saved subscription for that card. Existing opt-ins and opt-outs are retained.

## What Changed

- Reuse the mint-day card boundary with an explicit UTC weekday.
- Both upcoming subscription-status endpoints stop inferring Automatic
  subscriptions for closed cards.
- Closed-card totals use the finalized subscription list.
- Direct card subscription and quantity changes reject closed cards.
- Automatic mode and top-ups remain available for future cards.

## Backend Impact

Existing services affected: `api` and `subscriptionsTopUpLoop`, which bundles
the shared mode updater. There are no new services, response shapes, entity or
migration changes, configuration changes, queues, or integrations. The system
shape is unchanged; no architecture-doc update is needed.

The daily finalization and allocation-generation jobs are unchanged. This fix
does not reconstruct historical settings or balances for a delayed/repeated
finalization run. Saved card records remain the source of subscription choice.
