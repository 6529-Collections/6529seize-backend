# App device grants and encrypted-message handoff

App grants authorize signed posts and encrypted DMs with one wallet signature. Connection sharing can carry encrypted fresh target-device keys and the wallet-signed grant, allowing the receiving Mobile or Core app to set up without a connected wallet. The API never receives the unlock secret; proxy shares cannot carry device setup, and one-time redemption remains wallet/target bound.

Encrypted messages create in-app notifications for eligible recipients with the sender, opaque chat handle and message sequence. The feed never stores message content. Push stays content-free and uses its own cooldown. Direct-message preferences apply.

Deploy **dbMigrationsLoop → api** for the nullable connection-share ciphertext column, then the companion frontend. No new service, queue or environment variable is introduced. Deploy pushNotificationsHandler for the updated encrypted-message push copy. Keep app-grant feature flags as configured until the release rollout.

Receiving-app acceptance with a real wallet-approved source link still needs staging validation, including iOS 16.4's encryption-only support and iOS 17+ signed posts. Core must refresh its renderer after the frontend merges. No deployment is performed by this implementation.

Follow-up corrects own-account roles in encrypted connection shares: the server checks the wallet's current profile and normalizes that role to the own-account target session, while rejecting proxy profiles. SQL reads include the ciphertext, and guarded transactional consumption permits only one concurrent consumer and no replay. Notification projection is shared by V1/V2. The new cause is an explicit additive API-contract extension. Group handles are fixed-size hex values validated at E2EE route boundaries.

Own-profile roles are canonical profile IDs selected by the existing authentication role resolver; they are compared as opaque IDs, consistently with the authentication context. The share tests use distinct UUID-shaped own/proxy roles. Redemption selects the complete consumed row after a guarded update wins, including encrypted setup; losing concurrent consumers return null before reading that row.

Chat invitations retain their content-free push wake. The push coalescing window cannot suppress in-app message notifications.
