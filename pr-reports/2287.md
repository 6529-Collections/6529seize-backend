# App device grants and encrypted-message handoff

App grants authorize signed posts and encrypted DMs with one wallet signature. Connection sharing can carry encrypted fresh target-device keys and the wallet-signed grant, allowing the receiving Mobile or Core app to set up without a connected wallet. The API never receives the unlock secret; proxy shares cannot carry device setup, and one-time redemption remains wallet/target bound.

Encrypted-message wakes also create generic in-app notification entries. Only opaque chat identifiers are persisted; the server stores no sender or message content. Existing content-free push delivery remains separate and is preserved if inbox insertion fails. Direct-message preferences apply.

Deploy **dbMigrationsLoop → api** for the nullable connection-share ciphertext column, then the companion frontend. No new service, queue or environment variable is introduced. Existing pushNotificationsHandler behavior is retained and does not need redeployment for this follow-up. Keep app-grant feature flags as configured until the release rollout.

Companions: [frontend #4541](https://github.com/6529-Collections/6529seize-frontend/pull/4541), [mobile #26](https://github.com/6529-Collections/6529-core-mobile/pull/26), [Core #278](https://github.com/6529-Collections/6529-core/pull/278).
