# PR Report: End-to-end content moderation backend

PR: https://github.com/6529-Collections/6529seize-backend/pull/1937
Branch: `agent-prxt/content-moderation` -> `main`
Related PRs: [Frontend PR #3791](https://github.com/6529-Collections/6529seize-frontend/pull/3791)

## Summary

Adds persisted personal visibility controls, reporting, permissive pre-publication screening, AI-assisted report assessment, and a reasoned occasional-moderator workflow for user-generated drops.

## What Changed

- Keeps report, hide, and block as independent actions with durable personal state.
- Escalates only narrow deterministic pre-publication signals to AI and rejects only high-confidence prohibited content; profanity and controversial speech remain allowed.
- Gives human moderator decisions transactional precedence over late AI assessments.
- Commits each report with its requested personal hide/block actions, denies moderation actions through profile proxies, and keeps moderated content visible to its author while redacting it for other viewers.
- Uses model-category allowlisting, normalized malicious-host matching with bounded-time token cleanup, and stable opaque queue cursors.
- Redacts globally unavailable content across drop APIs, parts, replies, quotes, notifications, pushes, and WebSocket updates.
- Records immutable moderation history and report snapshots containing text, context, media metadata, and asynchronous attachment verdict/hash metadata.

## Backend Impact

- New services: None.
- Changed services: `api`, `pushNotificationsHandler`, and `dbMigrationsLoop` entity registration.
- Planned/deployed services: `dbMigrationsLoop`, then `api`, then `pushNotificationsHandler`; not deployed by request.
- API: Adds personal moderation/report endpoints, moderator access/queue/decision endpoints, and drop moderation presentation fields.
- DB/entities/migrations: Adds eight additive moderation tables for blocks, hidden drops, reports, drop/profile states, roles, audit history, and pre-publication decisions.
- Queues/events/integrations: Filters stored/read/push notifications and emits recipient-scoped moderation WebSocket updates; Bedrock is invoked only after narrow deterministic signals or submitted reports.

## Config / Env

- `CONTENT_MODERATOR_PROFILE_IDS`: optional comma-separated moderator profile IDs. Falls back to `DEVS_6529_MENTION_PROFILE_IDS` when unset. Access checks do not persist configured IDs as roles. Configure on the API runtime.
- `CONTENT_MODERATION_BLOCKED_HOSTS`: optional comma-separated exact or parent host list for deterministic known-unsafe URL rejection. Configure on the API runtime; an empty value disables this direct-rejection list.
- `CONTENT_MODERATION_BEDROCK_MODEL_ID`: optional moderation-specific Bedrock model override. Falls back to the existing configured/default Anthropic model.

## Release Notes

Users gain independent report, hide, and block controls. Posts receive a permissive pre-publication safety check, and authorized occasional moderators can review reports, quarantine or remove content, and suspend or reinstate posting profiles with recorded reasons.

## Risks / Follow-Ups

- Backend must be deployed before the related frontend so clients receive the moderation fields and endpoints they consume.
- The known-unsafe host list requires operational curation; leaving it empty preserves permissive behavior but disables direct URL rejection.
