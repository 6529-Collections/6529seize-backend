# PR Report: End-to-end content moderation backend

PR: https://github.com/6529-Collections/6529seize-backend/pull/1937
Branch: `agent-prxt/content-moderation` -> `main`
Related PRs: [Frontend PR #3791](https://github.com/6529-Collections/6529seize-frontend/pull/3791)

## Summary

Adds persisted personal visibility controls, reporting, permissive pre-publication screening, AI-assisted report assessment, and a reasoned occasional-moderator workflow for user-generated drops.

## What Changed

- Keeps hide and block available as independent actions while every report automatically hides the post for its reporter.
- Exposes the reporter's latest active or resolved report state in drop presentation data, prevents duplicate open reports, and supports audited withdrawal of open reports without undoing the personal hide.
- Adds a caller-scoped, cursor-paginated report-history endpoint for Preferences that returns the reporter's own reason, author identity, public outcome, current wave identity, and a sanitized immutable snapshot of the reported post. It excludes reply-parent evidence, internal upload and attachment identifiers, hashes, scanner verdicts, AI assessment data, moderator identity, internal notes, and other reporters.
- Treats a block as a directional, privacy-preserving mute: one-to-one messages remain deliverable under normal admission rules while the blocker's existing and future conversations are effectively muted and blocked-author content remains revealable.
- Keeps group conversations usable while suppressing blocked-author post presentation, ordinary notifications, push notifications, and unread counts for the blocker without affecting other members.
- Escalates only narrow deterministic pre-publication signals to AI and rejects only high-confidence prohibited content; profanity and controversial speech remain allowed.
- Evaluates structured private-data signals generically: genuine usable identifiers can be rejected regardless of ownership, while clearly labelled fictitious, sandbox, test, example, redacted, or documentation data remains allowed.
- Gives human moderator decisions transactional precedence over late AI assessments.
- Rejects semantically contradictory AI payloads: neutral allow/no-violation results must use category `NONE`, while reject/review/quarantine results must use a substantive category and follow the existing fail-open or human-review fallback.
- Commits each report with its requested personal hide/block actions, denies moderation actions through profile proxies, and keeps moderated content visible to its author while redacting it for other viewers.
- Uses model-category allowlisting, normalized malicious-host matching with bounded-time token cleanup, and stable opaque queue cursors.
- Runs Bedrock pre-publication evaluation before opening the drop-write transaction, applies a request deadline, and resolves runtime model configuration after secrets load.
- Prevents duplicate open reports, applies a permissive per-profile report rate limit, and counts only open reports when prioritizing the queue.
- Returns current author and reporter handle/PFP data with moderation queue items so occasional moderators can identify both sides of each report without relying on opaque profile IDs.
- Separates open and resolved report queues, returns moderation dashboard counts, and provides a paginated suspended-profile register for direct reinstatement.
- Makes moderator decision notes optional while preserving every state transition in the immutable audit history.
- Redacts globally unavailable content across drop APIs, parts, replies, quotes, notifications, pushes, and WebSocket updates.
- Records immutable moderation history and report snapshots containing text, context, media metadata, and asynchronous attachment verdict/hash metadata.
- Adds a standalone backend feature guide covering publication decisions, personal controls, reports, global moderation, posting suspension, retention, service ownership, and rollout order.

## Backend Impact

- New services: None.
- Changed services: `api`, `pushNotificationsHandler`, and the daily `dbMigrationsLoop` migration/retention job.
- Planned/deployed services: `dbMigrationsLoop`, then `api`, then `pushNotificationsHandler`; not deployed by request.
- API: Adds personal moderation/report endpoints, including `GET /content-moderation/reports/mine`, moderator access/queue/decision endpoints, and drop moderation presentation fields.
- DB/entities/migrations: Adds eight additive moderation tables for blocks, hidden drops, reports, drop/profile states, roles, audit history, and pre-publication decisions.
- Queues/events/integrations: Filters stored/read/push notifications and emits recipient-scoped moderation WebSocket updates; Bedrock is invoked only after narrow deterministic signals or submitted reports.

## Config / Env

- `DEVS_6529_MENTION_PROFILE_IDS` and `CONTENT_MODERATOR_PROFILE_IDS`: content moderator access is the deduplicated union of the existing developer-mention recipients and any optional additional moderator profile IDs. Access checks do not persist configured IDs as roles. Configure both on the API runtime as needed.
- `CONTENT_MODERATION_BLOCKED_HOSTS`: optional comma-separated exact or parent host list for deterministic known-unsafe URL rejection. Configure on the API runtime; an empty value disables this direct-rejection list.
- `CONTENT_MODERATION_BEDROCK_MODEL_ID`: optional moderation-specific Bedrock model override. Falls back to the existing configured/default Anthropic model.
- `CONTENT_MODERATION_REPORTS_PER_HOUR`: optional per-profile report submission ceiling; defaults to a permissive 100.

## Release Notes

Users gain report, hide, and block controls; reporting automatically hides the post and an open report may be withdrawn without restoring it. Posts receive a permissive pre-publication safety check, and authorized moderators can work separate open, resolved, and suspended-profile views to review reports, quarantine or remove content, and suspend or reinstate posting profiles.

## Risks / Follow-Ups

- Backend must be deployed before the related frontend so clients receive the moderation fields and endpoints they consume.
- The known-unsafe host list requires operational curation; leaving it empty preserves permissive behavior but disables direct URL rejection.
- Pre-publication decision records are retained for 30 days and pruned by the daily `dbMigrationsLoop` schedule.
