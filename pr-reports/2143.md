# PR Report: Drop Forge Automated Launch Backend

PR: [Backend #2143](https://github.com/6529-Collections/6529seize-backend/pull/2143)
Related PR: [Frontend #4207](https://github.com/6529-Collections/6529seize-frontend/pull/4207)

## Summary

Adds a manually armed backend operator for claim initialization, subscriber
and selected category airdrops, and phase updates. An EventBridge Lambda uses
an AWS KMS secp256k1 wallet with creator-admin permission. Both launch execution
and asynchronous EMMA preparation are disabled by default.

## Behavior and safeguards

- Launch inputs freeze published metadata, derived recipients, Merkle roots,
  mint windows, signer, creator/proxy scope, and payment receiver. Revisioned
  controls support arm, pause, resume and cancel; terminal ledgers cannot reset.
- A wallet-wide transaction ledger persists signed bytes and their hash before
  broadcast. Retries use the same transaction, reconcile confirmed canonical
  receipts, and block unknown nonce consumption, reverted actions, source or
  configuration changes, permission loss, and missed windows.
- Action reports use a configured operations wave. Errors tag
  `@dropforgers6529`, resolving manually supplied profile IDs through existing
  visibility and notification rules. Wave posts and acknowledgements commit
  together; failed wave delivery reaches the invocation alarm.
- EMMA phase and finalize jobs have stable request IDs, durable status and
  downloadable results. Preparation writes, proofs and results commit together;
  retries reuse the result. Finalization inserts normalized data in bounded
  batches and TDH enrichment reads only relevant wallet sets.

## Operational boundaries

The signer pays gas; mint proceeds retain the configured receiver. Pay Artist,
owner-only admin management, wallet funding, KMS/IAM provisioning, winner
selection and deployment are excluded. Existing synchronous EMMA endpoints
remain compatible; their buttons still need frontend adoption of the job APIs.
Production traces are needed to confirm the reported timeout cause.

## Configuration and rollout

See [operator guide](../docs/drop-forge-auto-launch.md) for environment names,
IAM/KMS restrictions, timing rules, recovery, and the full service deployment
plan. Entity sync precedes API, the disabled worker, and affected wave producers.
No data migration or deployment is performed by this task. Wave/bot/recipient
IDs, KMS key/address, gas budgets, and EMMA service credentials are supplied
manually before enablement. Start with a separately authorized Sepolia exercise.

## Remaining risk

Live KMS signing, on-chain execution, IAM deployment, production wave delivery,
and large production EMMA workloads have not been exercised. Previously signed
transactions can mine after pause, cancellation or a deadline; manual recovery
must reconcile the original hash/nonce before further operations. The full
local test suite stalled before reporting results; focused integration coverage
and compilation provide the local validation evidence for this change.
