# Drop Forge launch and EMMA processing

PR: [Backend #2143](https://github.com/6529-Collections/6529seize-backend/pull/2143)
Companion: [Frontend #4207](https://github.com/6529-Collections/6529seize-frontend/pull/4207)

EMMA now accepts one durable Process and Finalize job, snapshots inputs from the three phases, processes subscriptions in checkpoints, finalizes and serves read-only
paginated lists. Refresh/retries discover committed progress rather than repeat
HTTP-bound preparation writes. Pending processing blocks conflicting edits/reset.

Craft Launch derives the existing Europe/Athens mint schedule from the calendar
and wakes initialization immediately. Phase subscriber airdrops run in their
respective transition gaps; Phase 2 and public subscribers share the second gap.
Public configuration changes only after Phase 2 closes. Admission checks each
transition's transaction/confirmation budget; deadlines can still be missed
because inclusion/finality is external. Republished metadata queues Update Claim,
retaining live mint parameters and completed allocation progress.

Research becomes eligible at 17:15 Europe/Athens the next day, fifteen minutes
after public minting closes. It tops up to `min(310, frozen Craft edition)` using
fresh on-chain total supply and requires the on-chain maximum to match Craft.
The reserved amount is rechecked before signing. Confirmed manual Research
transactions count toward the target; an already-filled target sends nothing.
Research completion updates the manual action flag and operations wave. The
launch remains active until this final step is reconciled. Older plans lacking
Research require reconciliation rather than silently completing. Pay Artist is
the sole excluded routine Launch action.

Manual wallet controls acquire a durable lease before submission. Verified
canonical evidence credits the declared category and only remaining allocations;
compatible initialized/configured claims are observed without another write.
Automation mirrors completed airdrop groups into existing manual flags. Unknown
nonce/supply, incompatible configuration, reverted transactions or reorgs block
rather than silently restart. Signed bytes/hash persist before broadcast and
retries use the same intent. Transactions outside the coordinated controls need
their hashes supplied; minted supply does not prove recipient delivery.

Every worker transition reports to the configured operations wave with readable
claim/action wording and transaction links. Failures tag @dropforgers6529 using
manually supplied eligible profiles. Reports/acknowledgements commit together;
new signing waits for earlier reports. Signed transactions still reconcile.

Both workers remain disabled by default. Provisioning AWS KMS/IAM, gas funding,
creator-admin grants and wave/profile/EMMA configuration is separate operator work.
The signer pays gas; mint proceeds retain the receiver. Pay Artist and owner-only
admin management remain outside automation. Live KMS/chain transactions,
production wave delivery and large production EMMA workloads have not been
exercised. See [operator guide](../docs/drop-forge-auto-launch.md) for deployment
ordering and recovery boundaries. No deployment or main merge is part of this task.

The final database rerun was unavailable because the local MySQL container did
not start. Earlier preparation, launch/lease and worker database coverage ran;
the final manual-receipt and metadata-supersession refinements have isolated
repository-boundary coverage. Repeat database validation before rollout.

A signed intent that never gains a receipt can retain the shared signer lock
indefinitely after pause/cancellation or a deadline. Empty receipt/mempool and
unchanged nonce observations cannot invalidate signed bytes. Automatic unlock
and late rebroadcast remain excluded. A supported recovery control must first
verify canonical nonce consumption by the original or a replacement transaction;
that control is deferred and is an enablement blocker for unattended operation.
Existing transaction-state complexity warnings are maintainability debt, not
permission to weaken these invariants. Broad worker/plan restructuring is deferred
from this bounded correctness pass; keep automation disabled pending review.
