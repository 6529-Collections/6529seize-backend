# Drop Forge launch and EMMA processing

PR: [Backend #2143](https://github.com/6529-Collections/6529seize-backend/pull/2143)
Companion: [Frontend #4207](https://github.com/6529-Collections/6529seize-frontend/pull/4207)

The global alert shortcut is `@drops6529`, configured with
`DROPS_6529_MENTION_PROFILE_IDS`. Dedicated worker role ARNs now come from the
selected protected GitHub environment and fail validation before deployment if
missing or malformed. The maintained [setup guide](../docs/drop-forge-auto-launch-setup.md)
covers wave/profile configuration, KMS wallet creation/address derivation, IAM,
runtime values and the initial rollout without contract-admin permission.

EMMA now accepts one durable Process and Finalize job, snapshots inputs from the three phases, processes subscriptions in checkpoints, finalizes and serves read-only
paginated lists. Refresh/retries discover committed progress rather than repeat
HTTP-bound preparation writes. Pending processing blocks conflicting edits/reset.

Craft Launch derives the existing Europe/Athens mint schedule from the calendar
and wakes initialization immediately. Phase subscriber airdrops run in their
respective transition gaps; Phase 2 and public subscribers share the second gap.
Public configuration changes only after Phase 2 closes. Admission checks each
transition's transaction/confirmation budget; deadlines can still be missed
because inclusion/finality is external. Republished metadata queues Update Claim,
retaining live mint parameters and completed allocation progress.

Research becomes eligible at 17:15 Europe/Athens the next day, fifteen minutes
after public minting closes. It tops up to `min(310, frozen Craft edition)` using
fresh on-chain total supply and requires the on-chain maximum to match Craft.
The reserved amount is rechecked before signing. Confirmed manual Research
transactions count toward the target; an already-filled target sends nothing.
Research completion updates the manual action flag and operations wave. The
launch remains active until this final step is reconciled. Older plans lacking
Research require reconciliation rather than silently completing. Pay Artist is
the sole excluded routine Launch action.

Manual wallet controls acquire a durable lease before submission. Verified
canonical evidence credits the declared category and only remaining allocations;
compatible initialized/configured claims are observed without another write.
Automation mirrors completed airdrop groups into existing manual flags. Unknown
nonce/supply, incompatible configuration, reverted transactions or reorgs block
rather than silently restart. Signed bytes/hash persist before broadcast and
retries use the same intent. Transactions outside the coordinated controls need
their hashes supplied; minted supply does not prove recipient delivery.

An unavailable RPC receipt block defers scheduled and recovery reconciliation
without changing completed work, signing again or releasing the nonce reservation.
Available blocks with conflicting hashes still trigger the existing reorg checks.

Every worker transition reports to the configured operations wave with readable
claim/action wording and transaction links. Failures tag @drops6529 using
manually supplied eligible profiles. Reports/acknowledgements commit together;
new signing waits for earlier reports. Signed transactions still reconcile.

Both workers remain disabled by default. Provisioning AWS KMS/IAM, gas funding,
creator-admin grants and wave/profile configuration are separate operator work.
The signer pays gas; mint proceeds retain the receiver. Pay Artist and owner-only
admin management remain outside automation. Live KMS/chain transactions,
production wave delivery and large production EMMA workloads have not been
exercised. See [operator guide](../docs/drop-forge-auto-launch.md) for deployment
ordering and recovery boundaries. No deployment or main merge is part of this task.

Recovery, launch worker and manual coordination database validation completed,
including the current manual-receipt and publication-supersession refinements.
The earlier local MySQL startup gap is closed for those paths. EMMA preparation
and finalization database suites were not rerun in this recovery change.

Authorized transaction recovery is implemented: exact action/nonce inspection,
asynchronous same-nonce speed-up/cancellation, existing replacement hash
verification, finalized winning evidence and exact mint-event allocation checks.
Settlement, completion flags, wallet release and reporting outbox commit together.
Cancellation/revert leaves entitlement outstanding; late original success is
credited without replay. Reviewed retries require finalized prior nonce evidence.
Late airdrop delivery is available after all minting closes with frozen remaining
allocations and fresh supply checks. Research retains its dynamic Craft-capped target.
A recovery-only switch allows exceptional handling while scheduled execution is
disabled; both flags remain off by default. No force-unlock or uncertain replay exists.

Focused recovery database validation completed, including request serialization
and rollback of settlement plus signer release on a persistence failure. This recovery pass does
not rerun the unchanged EMMA processing/finalization suites.
Live KMS transactions and production wave delivery remain unexercised. Existing
worker/plan complexity debt is deferred; review the monetary/nonce boundaries before
rollout. Contract admin actions outside coordinated controls still require proof.

Generic manual airdrop reconciliation excludes the dynamic Research placeholder
and confirms only batches actually credited by that proof. An ordinary undeclared
subscriber/category airdrop cannot mark Research complete or suppress its top-up.

The legacy subscription allowlist route uses the Subscription Admin middleware
before preparation. Phase preparation remains backed by its durable result and
does not regain HTTP response caching during base updates. Unauthorized callers
cannot invoke preparation or receive previously cached admin data. This keeps
main's authorization fix and the agreed asynchronous preparation behavior.

EMMA processing uses the clicking distribution administrator's authorization, encrypted for the specific job using the existing environment JWT secret. Credentials clear after input capture or terminal failure. Expired/denied access pauses for Sign in to resume; renewed access continues the same job and checkpoints. No configured EMMA service token is required.

Launch actions run in scheduled phase groups with independent readiness, minute-spaced unsigned retries and on-chain completion detection. Manual initialization and exact recipient/amount delivery proofs are skipped without replay, even after an earlier deadline. Later groups continue after unsuccessful earlier work; uncertain signed nonces still require reconciliation. Every execution, failed attempt and detected-complete skip has a durable wave report. Research preserves supply owed to outstanding fixed allocations.

Fully missed launches do not occupy the scheduled candidate limit, while their manual evidence remains reconcilable. Metadata readiness follows the compatible current phase rather than a stale earlier phase checkpoint.
