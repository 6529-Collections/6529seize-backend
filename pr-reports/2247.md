# Local shared Memes calendar

Craft no longer needs the frontend calendar API to resolve a new claim's season.
It uses a bundled pure TypeScript module, while retaining the database's permitted
season window and fallback.

Canonical source: [frontend #4454](https://github.com/6529-Collections/6529seize-frontend/pull/4454).
Both repositories carry identical versioned sources and SHA-256 manifests. The
[maintenance guide](../docs/shared-memes-calendar.md) describes synchronization,
Athens timezone handling, historical overrides and phase windows.

[Automation #2143](https://github.com/6529-Collections/6529seize-backend/pull/2143)
stacks on this foundation to freeze UTC launch plans. Other existing calendar HTTP
consumers are unchanged. Merge the calendar pair before the automation pair and
retarget the dependent PR after the foundation merges. No deployment is included.

Future mint-day overrides now preserve forward/inverse numbering agreement. Sync
prunes only unchanged obsolete manifest-owned files and preserves local edits and
unrelated files. Exact DST duration and sync-cleanup regressions are covered.
Overrides retain the existing one-mint-per-eligible-date model; an extra override
does not create another mint on an already eligible date.
The existing claim-season tests already cover historical, distant-future and invalid
claims falling back to the database creation window; no fallback was removed.
