# PR Report: ETH price recovery contention

PR: https://github.com/6529-Collections/6529seize-backend/pull/2121
Branch: `agent-prxt/eth-price-recovery-contention` → `main`
Related PR: https://github.com/6529-Collections/6529seize-backend/pull/2120

## Summary

Historical recovery could time out, continue issuing repairs under contention,
and subsequently fail the live-price insert. The collector now commits the live
quote first and stops historical work after a database failure. A learned
one-candle batch also exposed an endpoint bug: recovery repeatedly selected the
existing row after a hole. Requests now exclude that boundary and advance into
the missing interval. Continuous small database batches now drain a gap within
the same invocation instead of waiting for each five-minute schedule tick.

## What Changed

- Historical coverage is daily before January 1, 2026 and five-minute from that
  date onward. Any saved sample covers its older UTC day; only entirely missing
  days are filled. Existing sparse history and extra rows remain intact. Reset
  uses the same split, including when resuming a legacy checkpoint. Daily retry
  state is separate from old five-minute omissions.
- Gap ranges exclude existing right endpoints and retain recoverable candles
  immediately before unavailable ranges. One-candle batches progress through
  interior holes. Logs count processed candles without claiming new inserts.
- Coinbase pages hold up to a day of five-minute candles or thirty daily candles.
  Database batches contain at most one hour of five-minute candles or one daily
  candle. Each batch commits before the next begins; gap discovery
  paginates past eight gaps. Lambda's remaining execution time bounds the run.
- Live quotes refresh between batches during long runs. Smaller learned batch
  limits still protect the database and grow gradually after sustained fast
  successful batches.
- Transaction USD corrections use persisted price intervals and indexed date
  ranges instead of repeated historical-price subqueries per transaction. Both
  recovery and transaction writers use the latest saved sample at or before the
  transaction, including a live quote saved earlier in the same invocation.
- Mint candidates come from affected transactions. Only their existing mint-stat
  rows are locked; full-token USD totals remain atomic with price/transaction
  correction.
- One structured collector error includes live-save status, failed ranges, and
  safe database-stage diagnostics. The same error is logged and thrown for
  handler deduplication; invocation failures and infrastructure alarms remain.
  A live-provider failure allows historical progress but remains visible in the
  final failure summary even when those historical batches commit.

## Backend Impact

Only `ethPriceLoop` changes. No database schema, entity, migration, API, frontend,
new service, or configuration change. Existing writer guards from #2120 remain.

## Risks / Follow-Ups

Check the previously failing range in staging before production promotion.
Live-first ordering protects the committed quote from a subsequent rollback,
but cannot remove external locks or prior database cleanup. A one-hour candle
batch is not a bound on transaction count or full-token mint aggregation work.
Recovery continues within an invocation until work finishes or the deadline
reserve is reached. Database workload, omitted candles, or failures can still
require later invocations. Use the stage diagnostics and read-only database lock/query-plan evidence if
contention persists.
