# PR Report: Rebuild check: recount community metrics from their events

PR: [#2570](https://github.com/6529-Collections/6529seize-backend/pull/2570)
Base: #2542's branch; merges after #2542 and after the TDH rebuild PR

## Summary

The rebuild check can now rebuild `metric_rollup_hour`, the table behind the community metrics routes. A rebuild recounts it from the tables its events left behind, by the UTC hour each event happened:

- four counters by event hour: drops, droppers, Main Stage submissions and Main Stage votes;
- two samples once a day: network TDH and consolidations formed;
- active identities as a lower bound of what identities did;
- three metrics not rebuilt, each with its reason.

Live writes and routes are unchanged. After a rebuild, hourly figures can differ from the live ones at hour boundaries.

## What Changed

- **The recount** (`src/metrics/metrics-rebuild.ts`, `metrics-rebuild.tables.ts`):
  - `recountMetricRollupHour` replaces the table in one transaction, one INSERT ... SELECT per metric. Hours come from arithmetic on the stored epoch values, not from the session's time zone.
  - `DROP` and `DROPPER_DROP` count drops created, deleted drops included.
  - `MAIN_STAGE_SUBMISSION` counts native submissions to designated Main Stage competitions, using live's own designation check. With `MAIN_STAGE_WAVE_ID` set, it also counts that wave's participatory drops and its winners from before native competitions, without counting the entry the drop use case writes for them again.
  - `MAIN_STAGE_VOTE` counts each vote change a voter made, valued at the change. The system's credit cuts are left out, because live records no rollup for them.
  - Rows the system writes without a rollup are left out everywhere: alert drops, priority alert drops and the help bot's reactions. A deleted drop keeps no title, so every deleted drop of the priority alert wave is left out, people's included.
  - `NETWORK_TDH` and `CONSOLIDATIONS_FORMED` are sampled at 00:00 UTC of each TDH day, from that day's last block. `CONSOLIDATIONS_FORMED` is sampled only with `MAIN_STAGE_WAVE_ID` set, as live does.
  - `ACTIVE_IDENTITY` counts drops created, reactions, boosts, waves created and rating changes the rater made. It can't see subscribes, boost removals, wave updates and deletes, pins, mutes, group changes, or removed reactions.
  - Not rebuilt: `TDH_ON_MAIN_STAGE_SUBMISSIONS`, `PROFILE_COUNT` and `XTDH_GRANTED`. Each would need a replay of state over time, which is not attempted.
- **A new metrics area** (`src/rebuild/manifests/metrics.manifest.ts`, one line in `manifests/index.ts`):
  - It owns `metric_rollup_hour` (INDEX) and probes `/api/community-metrics/series` over a fixed window.
  - Its seed runs after every other area's seeds and replaces the seeded world's live rows with the recount, so the check compares a recount with a recount.
  - Its rebuilder runs after the rebuilders of the tables it reads.
  - The summary route is waived, because it depends on the day the check runs.
- **TDH area** (`tdh.manifest.ts`): the table and the series probe move out. `probe-fixture.ts` loses `PROBE_TO_MS`, which nothing uses any more.
- **Tests:**
  - Unit tests cover the hours, the metric list, the left-out rows, the active-identity SQL and the step order.
  - A DB test covers the recount on seeded rows.
  - A DB test compares the recount with live rows written within one hour through the drop use case and MetricsRecorder, and shows the hour-boundary case where they differ by design.

## Backend Impact

**Deploy:** none. No Lambda, route, schema, schedule, queue or alarm change; only the rebuild check imports the new module.

**Live behaviour.** Unchanged: the site writes and reads `metric_rollup_hour` as before.

**Other services.** None.

## Config / Env

None. The recount reads `MAIN_STAGE_WAVE_ID`, `ALERTS_WAVE_ID`, `ALERTS_BOT_PROFILE_ID` and `PRIORITY_ALERTS_WAVE` as live does.

## Rollback

Revert the PR. Nothing to undo in data.

## Risks / Follow-Ups

- **After a rebuild,** hourly figures can differ from the live ones at hour boundaries, daily samples sit at 00:00 of their TDH day, and active identities is a lower bound of what identities did. Live numbers are unchanged.
- **Merge order.** This PR and the TDH rebuild PR both edit `tdh.manifest.ts`. The table's entry conflicts, but the series waiver merges in without a conflict, so whoever merges second removes it by hand. They then check that no `metric_rollup_hour` entry and no series waiver are left. No check catches a leftover waiver.
- **The series probe** has data only when an area seeds events in its window. On #2542 alone the table stays empty.
