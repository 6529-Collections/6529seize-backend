# PR Report: Rebuild check: rebuilders that own columns of a table another rebuilder writes

PR: [#2577](https://github.com/6529-Collections/6529seize-backend/pull/2577)
Base: #2569's branch; merges after #2569

## Summary

Some tables get their rows from one area, while another area's loops keep a few of their columns up to date. For example, the identity area writes the rows of `identities`, and the TDH loops set its `tdh` and `basetdh_rate`. A rebuilder can now own columns of a table whose rows another rebuilder writes. MySQL column grants enforce the split, and the run checks it. Nothing outside the rebuild check and its docs changes.

## What Changed

- **Owned columns** (`src/rebuild/manifest.types.ts`, `step-writes.ts`). A rebuilder can list `{ table, columns, reason }` in `writes`. The step-writes helpers keep row writes apart from column writes.
- **Registry** (`registry-check.ts`). It refuses:
  - an owner that is a seed, or of a table that isn't INDEX;
  - an owned write with no columns, or no reason;
  - a write with both columns and a partition;
  - two owners of one column;
  - owning a partition or checkpoint column;
  - owners of a table with no row writer;
  - an owner that doesn't run after the row writer. The message gives the `after` to add;
  - a step that both writes a table's rows and owns columns of it.

  A writer of the table that reads it waits on no owner. Any other reader waits on every writer, owners included.
- **Grants** (`guard/db-grants.ts`, `run/runner.ts`).
  - The row writer gets `SELECT` and `DELETE` on the table, `INSERT` on every column, and `UPDATE` on every column no owner has.
  - An owner gets `SELECT` on the table, and `UPDATE` on its own columns only.
- **Refusals** (`run/refusals.ts`). When MySQL refuses a step (errors 1142 and 1143), the run names the step, the command, the column or table, and why: a column owner's column, a table the step only owns columns of, or a table its writes don't name.
- **Reset** (`run/runner.ts`, `stack/mysql-admin.ts`).
  - When the table's last running row writer is done, the running owners' columns are reset on every row: to the default, to NULL, or for a NOT NULL column without a default, to its type's zero.
  - When no row writer of the table runs, the reset happens after the kept copy.
- **Absent owners** (`run/runner.ts`). An owner that doesn't run has its columns saved with each row's key before the drop and put back after the last running row writer. Probes still read them. The comparison leaves them out, the report lists them with why, and `--final` fails on them.
- **Checks** (`run/runner.ts`).
  - Before and after each owner runs, the run digests its table without the owned columns and the columns MySQL writes itself. Any change fails the run.
  - At run start it fails on an owned column that is missing, in the primary key, or not resettable, and on a table with owners but no primary key.
- **Exempt columns** (`manifest.types.ts`, `registry-check.ts`). `exemptColumns: [{ column, reason }]` lists named clock or random columns a step can't reproduce, each until a dated follow-up derives it from block times. They are left out of the comparison and listed with their reason. A column can't be both exempt and owned.
- **Docs** (`docs/rebuild-check.md`).
  - Column owners and the new registry checks.
  - Why a cursor that its rebuilder rewrites is INDEX rather than EPHEMERAL, with `identity_chain_mirror_state` as the example.

## Risks / Follow-Ups

- **What a split needs.**
  - The table needs a primary key.
  - Each owned column must sit outside the key and outside any partition or checkpoint column, and must be one the run can reset.
  - The row writer's live code may insert owned columns but not update them.
  - No production change is needed. The identity mirror's insert of `tdh` and `basetdh_rate` runs unchanged.
- **Cost.** The digest reads the whole table before and after each owner, and an absent owner's columns are copied out and back once, which makes large tables slower.
- **Declarations.** The identity and TDH changes declare their columns of `identities`:
  - the identity mirror writes the rows, with `rep`, `cic` and `level_raw`;
  - TDH owns `tdh` and `basetdh_rate`;
  - the four xTDH columns are zeroed at switch-on and need no owner.
