# PR Report: Fix release attribution and frontend production baselines

PR: https://github.com/6529-Collections/6529seize-backend/pull/1869
Branch: `agent-prxt/release-attribution-notes` -> `main`
Related PRs: https://github.com/6529-Collections/6529seize-frontend/pull/3504

## Summary

Deployment notifications once again show contributors, but attribution is now
bound to the exact authenticated Release Bus operation or documented manual
deployment evidence. Frontend production release notes also recognize both
approved production workflows and bridge safely between their histories.

## What Changed

- Labels an initiator as Release Train only when the allowlisted GitHub App
  supplies a valid train, operation, workflow, repository, environment, and
  service identity.
- Keeps manual initiators separate from contributor attribution and preserves
  mapped 6529 mentions plus safe unmapped fallbacks.
- Scopes Release Bus contributors to newly introduced or explicitly selected
  candidates, then narrows backend attribution to each service deploy plan.
- Derives manual backend contributors from the exact pull request, deployed
  SHA, and affected service while omitting unverifiable attribution.
- Filters automation identities and deduplicates human contributors
  case-insensitively.
- Preserves per-PR release-note contributors independently of CI-drop
  attribution.
- Selects frontend production baselines from an explicit allowlist containing
  the manual and Release Bus production workflows, including safe transitions
  in either direction.
- Exposes distinct outcomes for CI-drop acceptance, release-note eligibility,
  enqueue failures, generation skips, deduplication, and publication.

## Backend Impact

- Changed services: `api`, `releaseNotesGenerationLoop`, `releaseBus`
- API: Extends the signed internal CI alert contract with Release Bus operation
  identity and contributor evidence fields.
- DB/entities/migrations: None.
- Queues/events/integrations: Carries optional immutable Release Bus identity
  through release-note queue messages and reports best-effort enqueue outcomes.
- Manual deploy tooling: Requires the exact represented pull request so service
  contributor scope can be proven.

## Config / Env

No new secrets or runtime configuration. Existing GitHub workflow tokens gain
read-only pull-request access for immutable contributor evidence.

## Compatibility and Rollout

Deploy this backend PR before frontend PR #3504. The receiver accepts the
legacy contributor payload during that transition but deliberately omits
unverified contributors; after the frontend update, the full signed operation
evidence contract is used. No deployment, Release Bus control change,
notification replay, or historical release-note publication is part of this
PR.

## Release Notes

Frontend production releases can generate notes from either approved
production workflow without selecting staging or unknown histories. Release
Bus runs prefer the previous successful Release Bus production run and bridge
the first run to the latest approved manual production baseline. Manual runs
continue to work and may transition back from Release Bus production history.
