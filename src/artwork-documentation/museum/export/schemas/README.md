# Pinned museum schemas

These original schema bytes are retained so the dossier can be validated without live network dependencies. `schema-lock.json` records each original URI, local filename and SHA-256. Imports are resolved through that catalogue; the upstream schemas are not rewritten.

- PREMIS 3.0: Library of Congress, https://www.loc.gov/standards/premis/v3/premis-v3-0.xsd.
- LIDO 1.1: ICOM-CIDOC LIDO Working Group, licensed CC BY 4.0. Retrieved from its official development repository blob `ebf601d46907b2cb978569ada3a1b9205e834d87` at https://gitlab.gwdg.de/lido/development, corresponding to `1.1/lido-v1.1.xsd`.
- XML and GML dependency schemas retain their original W3C and Open Geospatial Consortium copyright and licence notices within the files.

The application bundle is generated by `node scripts/build-artwork-schema-bundle.cjs`; use `--check` to verify it. The tests validate actual generated museum records against the complete pinned XSD closure. Linked Art has a separate pinned JSON-LD context under `../schema/`.

The bundle generator packages original bytes; it is not an XML resolver. A validator must resolve each request by its complete original URI in `schema-lock.json`, verify that entry's SHA-256, and return the bytes with the original URI as their base URI. Relative includes then resolve against that original URI, rather than against the hashed local filename. Do not resolve by basename: distinct upstream directories can contain different schemas with the same name. Unlisted requests must fail with network access disabled. The consuming application change supplies this resolver as `LockedResolver` in `scripts/validate-artwork-dossier.py`, and uses it to compile and validate both schema closures offline.

IIIF Presentation 3 context bytes are from https://iiif.io/api/presentation/3/context.json (retrieved 2026-09-12). The independent JSON Schema is from IIIF/presentation-validator commit fb5bd9039494701dc7472cdcaffe83fb5a212463, schema/iiif_3_0.json. Original bytes and SHA-256 digests are pinned in schema-lock.json. The IIIF Presentation specification and context are credited to the IIIF editors and contributors under the specification's CC BY 4.0 notice: https://iiif.io/api/presentation/3.0/. The schema is an independent validation aid, not a claim that a draft's unserved media URLs are a deployed IIIF service.

The pinned IIIF validator contains an upstream `"type:"` typo in selector value constraints. Draft-07 ignores that keyword, so this schema alone does not reject non-string selector values. Preserve the original bytes and digest; consumers must separately enforce string selector values when producing or validating such selectors. Passing this schema alone is not a complete IIIF conformance claim.
